## 2. The model, in exponents (base r = group order)

Let `B = r^beta` be the factor-base size, `m >= 2` the arity, and let one
decomposition attempt cost `B^k r^{o(1)}` ("enumeration order" `k`; `theta` in
2ef5c8). Two oracle semantics:

- **all-decompositions** (exhaustive sweep, MITM, any table oracle): one
  attempt returns every decomposition of its target. Expected relations per
  attempt `B^m/(m! r)` (H1), so collecting `B` relations (H2) takes
  `max(1, r/B^{m-1}) r^{o(1)}` attempts:
  `attemptsAll(m, beta) = max(0, 1 - beta (m-1))`.
- **one-decomposition** (root-finding "first hit", a SAT solve stopping at the
  first model, a lattice oracle returning one root): at most one relation per
  attempt, so `B` successes are needed and each attempt succeeds with
  probability `min(1, B^m/(m! r))`:
  `attemptsOne(m, beta) = max(0, 1 - beta m) + beta`.

With sparse linear algebra at `B^2 r^{o(1)}` (H3):

```
costAll(m, beta, k) = max( attemptsAll + k beta , 2 beta )
costOne(m, beta, k) = max( attemptsOne + k beta , 2 beta )
```

## 3. Theorems (all proved in the Lean file; names in brackets)

Let `m >= 2`, `beta > 0`, `k >= 0` (reals).

1. `costAll >= 2/(m+1-k)` for `0 <= k <= 2`, `k <= m-2` [costAll_ge_small],
   attained at `beta = 1/(m+1-k)` [costAll_small_attained].
2. `costAll >= k/(m-1)` for `0 <= k <= m-1` [costAll_ge_large], attained at
   `beta = 1/(m-1)` when `k >= 2` [costAll_large_attained].
3. `costAll >= 1` for `k >= m-1` [costAll_ge_one]; exhaustive `k = m-1`
   [exhaustive_ge_one].
4. Thresholds: `2/(m+1-k) < 1/2 <=> m > k+3` [small_threshold];
   `k/(m-1) < 1/2 <=> 2k < m-1` [large_threshold]. Free oracle: `m >= 4`
   [free_oracle]; linear: `m >= 5` [linear_oracle]; quadratic: `m >= 6`
   [quadratic_oracle]; arity 3 with a free oracle ties 1/2 exactly
   [arity_three_free_ties].
5. **Meet-in-the-middle never**: `k >= m/2  =>  costAll > 1/2` at every arity
   [mitm_never_sub_generic].
6. One-decomposition oracles are never cheaper: `attemptsAll <= attemptsOne`
   (equality below saturation `beta m <= 1`) [attemptsAll_le_attemptsOne,
   costAll_le_costOne]; `costOne >= 2/(m+1-k)` for `0 <= k <= 1`
   [costOne_ge_small], attained at `beta = 1/(m+1-k)` [costOne_small_attained];
   `costOne >= (1+k)/m` for `1 <= k <= m-1` [costOne_ge_enum], attained at
   `beta = 1/m` [costOne_enum_attained].
   For `k >= 2`, `m >= 3` this is strictly worse than `k/(m-1)`: the
   oracle's return semantics move the exponent (e.g. m = 7, k = 2: 1/3 vs 3/7).
7. Non-vacuity: `(m, beta, k) = (5, 1/5, 1)` satisfies every hypothesis and
   gives `costAll = 2/5 < 1/2` [main_hyps_satisfiable]: in the model a
   linear-cost oracle at arity 5 is sub-generic.
8. Proves-too-much controls at `m = 3, k = 0` (where the full model ties):
   dropping H3 gives 1/3 [needs_H3_linear_algebra]; dropping H1 gives
   `max(k beta, 2 beta) -> 0` [needs_H1_failure_term]; dropping H2 gives 2/5
   [needs_H2_relation_count]; H4 in the other direction: m = 4 is sub-generic
   at k = 0 and not at k = 1 [needs_H4_oracle_order].

Closed form: `E*_all(m, k) = 2/(m+1-k)` for `k <= 2`, `k/(m-1)` for `k >= 2`
(`k <= m-1`), `>= 1` beyond; `E*_one(m, k) = 2/(m+1-k)` for `0 <= k <= 1`,
`(1+k)/m` for `1 <= k <= m-1`.

Derivation of theorem 1 (the others are the same shape): for
`beta <= 1/(m+1-k)` the first term is `1 - beta (m-1-k) >= 1 - (m-1-k)/(m+1-k)
= 2/(m+1-k)` because `m-1-k >= 0`; for `beta >= 1/(m+1-k)` the second term is
`2 beta >= 2/(m+1-k)`. At `beta = 1/(m+1-k)` both terms equal `2/(m+1-k)`.

## 4. What this decides, and what it does not

- It upgrades the obstruction of `LEAD-ICE-generic-oracle-arity-cost-floor`
  from kind `cost_model` to kind `proof` **within the model H1-H4** (becomes
  `theorem` only after `machine_verified` plus a separate sheriff review): no
  enumerative oracle of order `k >= (m-1)/2` reaches the generic exponent at
  any arity, which covers exhaustive and meet-in-the-middle oracles, and
  replaces the measured "zero in-domain sub-rho cells" (binary, n <= 83) with a
  statement for every `r`, prime or binary.
- It sharpens `revisit_when` on that lead and the next_action of
  `LEAD-ICE-charged-toy-ic-exponent-vs-rho` to one measurable number: the
  fitted enumeration order `k` of a candidate oracle (and its return
  semantics). An oracle matters only if `k < (m-1)/2` (all-decompositions) or
  `k < m/2 - 1` (one-decomposition).
- It does **not** prove that index calculus cannot beat rho over F_p: the open
  class `k < (m-1)/2` is a statement about the model, and no construction is
  known. It does not touch non-enumerative oracles that read coordinates
  algebraically with cost not of the form `B^k` (Groebner, SAT, lattice
  oracles have a measured `k`; see the experiment spec).
- H1 is the random-model mean; a non-generic yield above `C(B+m-1, m)/N` would
  change H1 (it is exactly the second revisit trigger already on the lead).
- The known-answer check of IDEA-20260830-3c0861 stays open: at `N = q^n`,
  `m = n`, `k = 0` the model predicts `q^{2n/(n+1)}`, which at n = 2 is
  `q^{4/3}` against the recalled literature `q^{2-2/n} = q` (Gaudry). The model
  is therefore known-pessimistic for the extension-field setting by exactly
  `2/(n(n+1))`; the Lean theorem proves the model, not its fidelity.

## 8. Memory coupling at m = 2 (second Lean target, `TASK-20261024-2be6ac`)

IDEA-20260830-4ab603: at arity 2 a free (k = 0) all-decompositions oracle over
an unstructured base is a sumset-membership query answered from a precomputed
table of the `B^2` pair sums, so its memory and precomputation exponents are
`2 beta`, not `beta`. In exponents (base `r`, `0 < beta <= 1`):

```
time2(beta)  = max(1 - beta, 2 beta)     -- attemptsAll(2, beta) + 0, and the linear algebra
mem2(beta)   = 2 beta                    -- the pair-sum table (and its precomputation)
```

Claim (file `formal/CryptoResearch/IC/MemoryCouplingArityTwo.lean`): for every
`beta`, `time2(beta) >= 2/3`, attained only at `beta = 1/3`; at that point
`mem2 = 2/3`, so the time-optimal point `(2/3, 2/3)` is dominated by BSGS at
`(1/2, 1/2)` on both axes; for every `beta` the time exponent is strictly above
`1/2`, so no point of the family beats rho or BSGS in time; and when the memory
exponent is at most `1/2` (`beta <= 1/4`) the time exponent is at least `3/4`.
Control: charging the memory at `beta` instead of `2 beta` (the uncorrected
IDEA-20260829-b5a2c8 reading) gives the point `(2/3, 1/3)`, which BSGS does not
dominate on the memory axis, so the table charge is load-bearing.
