## 2. Proposed responsibility boundary and receipt bootstrap

The following is a **proposed interface**, not an existing assembled workflow. Let `W` be the future task/session’s actual, recorded worktree directory on its actual host. No value for `W`, its device or its mount is asserted here.

| Component | Responsibility and state |
| --- | --- |
| Source selector | **To compose:** supply the exact C/P commit:path pins, expected hashes, task ID, batch, session/owner and `W`. Reject changed or missing source bytes. A configuration resolver is not a session receipt. |
| Bootstrap admission authority | **Missing:** authorize a narrowly bounded *receipt-only* host process before it starts. Starting the emitter is `starts_process`; it cannot be relabeled `inspect_static` (`j3-global-stop-repair.yaml:L59–84`; `j3-closure-v5.yaml:L56–83`). |
| Binding emitter | **Exists, host-dependent:** from cwd exactly `W`, the pinned v2 script obtains `hostname` and the device/mount of `.` using its literal executable paths. Failure emits no substitute binding (`emit_host_binding_v2.sh:L64–85, L124–199`). Availability of those paths on a future host is unknown. |
| Task-owned receipt writer | **Missing composition:** capture exact command, literal and resolved cwd, exit status, raw stdout and stderr, source pins and task/session identity; parse successful JSON; write the **complete** v2 runtime receipt once under that task’s exclusive scope. Do not accept a pasted binding or overwrite a prior receipt (`emit_procedure_v3.md:L22–42`). |
| Independent verifier | **Procedural requirement; composed interface missing:** in a separate session on the **same host**, verify trusted absolute executable identity and run an independent `hostname` and `df -P W`. Compare normalized host, device and mount with the sealed receipt and separately sourced observation. The verifier must identify the actual `W`, not reuse the historical `/Volumes/SSD990/...` example (`emit_procedure_v3.md:L44–54`; `receipt-schema-v2.yaml:L109–176`). |
| Admission evaluator | **Missing:** combine full inherited schema, v2 binding, typed observation, operation, PB-3, resource and global STOP rules. `check_receipt_v3.py` is only a presence/hash component. |

**Proposed state machine for one identity:** `SOURCE_PINNED → BOOTSTRAP_AUTHORIZED → EMIT_CAPTURED → OWN_RECEIPT_SEALED → INDEPENDENTLY_VERIFIED → ADMISSION_EVALUATED`. Every failed or unknown edge goes to `J3_STOP`; no target-task dispatch, materialization or other host-effecting operation follows. The receipt-only emitter itself has a host effect, so `BOOTSTRAP_AUTHORIZED` requires a separate, explicit pre-effect authority and scope. **That interface is absent in the inspected sources.** Calling emission “static inspection” or first dispatching the target task to obtain its receipt would make the rule circular. The draft therefore stops before emission until that bootstrap authority is specified.

At emission, `df -P .` must describe cwd `W`; independent `df -P W` must describe the same current device and mount on the same host. Record both the literal and resolved `W` so a historical path or symlink is not silently substituted. A sealed receipt belongs only to the named task/session; its raw bytes and content hash are immutable. Trusted-path checks record literal path, realpath, SHA-256, UID/GID, file type, executable bit and ancestor ownership/permissions, and stop on missing or mismatched executables (`emit_procedure_v3.md:L9–20`). This accepts the **trusted host, runtime and OS** limit: metadata and same-host comparison do not authenticate binaries, loaders, filesystem reporting or a malicious emitter (`receipt-schema-v2.yaml:L178–214`; `DEC-20260909-0581c6.yaml:L35–40`).

## 3. Proposed admission decision procedure

**Inputs:** sealed raw receipt and its exclusive task/session ownership record; C/P source manifest; exact `W`; requested action, schema version, effect class and applicability; independently obtained same-host binding and typed host observation; current trusted UTC validation time; closed PB-3 manifest and model; protocol-v7 caps and any applicable CT records; exact publication, task ownership and session-admission evidence. **Outputs:** a reasoned `J3_STOP`, or an *admission candidate for the named action only* after every applicable check passes. A candidate is not scientific approval or permission to exceed another gate.

1. **Custody and complete receipt.** Verify pinned bytes and task/session/`W` identity; parse the entire sealed receipt, not just its binding. Validate every inherited v1 field and type, then the v2 additions and provenance, before the binding rule. The source does not provide an exhaustive v1 grammar or a composed validator, so this step is currently **unevaluable → STOP**. An absent receipt, a v1-only binding or caller-substituted active binding also STOPs (`receipt-schema-v2.yaml:L18–96`).
2. **Finite binding rule.** For each of `host_id`, `filesystem_id`, `filesystem_mount`, reject absent, JSON null and non-string first. Trim only U+0020, U+0009, U+000A, U+000D, U+200B, U+200C, U+200D, U+2060 and U+FEFF at the edges; preserve host case, lowercase the device ID, strip its trailing `/`, and strip mount trailing `/` except root. Reject empty and case-insensitive literal `null`. Apply this **once**, then require equality of all three normalized observation values to the task receipt, never to a caller value (`receipt-rules-v3.json:L4–44`). Interior characters and other invisible Unicode remain outside the repair. The `///` mount input is an unresolved normative boundary: the checker chooses `/`, but the decision does not certify that choice as uniquely correct; proposed admission stops on that unresolved input (`DEC-20260909-0581c6.yaml:L31–35`).
3. **Independent current observation.** Verify `hostname` and `df -P W` on the same host and compare host/device/mount to the receipt. Require `observation_status=known`; string identities; unsigned 64-bit byte counts for free disk and memory; parseable RFC3339 `observed_at`; `clock_source=UTC_wall_clock`; integer `skew_seconds` in `[0,300]`; and `observed_at ≤ now + skew` plus `now − observed_at ≤ 3600 + skew`. Wrong unit/type, future, stale, mismatch or inability to verify STOPs (`j3-global-stop-repair.yaml:L85–103`). No current observation was taken in this turn.
4. **Action and costs.** Require exact membership in the operation and effect enums, derive host-resource applicability from action **or** effect, and reject absent, false or contradictory labels. Only `inspect_static` has the declared no-host-effect branch; emission is not that branch (`j3-global-stop-repair.yaml:L57–84`; `j3-closure-v5.yaml:L56–83`). Enforce the closed PB-3 top terms, caps, registered formula operands, exact nested model keys, units, conservative bounds, residual accounting and merge/I/O bindings; unknown or extra operands STOP (`j3-global-stop-repair.yaml:L104–143`; `j3-closure-v5.yaml:L132–260`).
5. **Resource and global decision.** Compare every applicable per-control and total envelope with typed observations and the unchanged protocol caps. Preserve existing failed and unknown materialization gates; do not treat a receipt, estimate or administrative PASS as a disposition change (`j3-closure-v5.yaml:L344–417`; `planning-gate-2.yaml:L534–558`). Any STOP dominates every pass across the closed dependent-action registry, with `resource_incomplete`, authorization unchanged and no scientific interpretation (`j3-closure-v5.yaml:L422–459`). No dispatch or target host effect precedes its admission.
