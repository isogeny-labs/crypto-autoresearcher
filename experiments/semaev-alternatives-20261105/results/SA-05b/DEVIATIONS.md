1. Square-divisibility filter not used at p = 2^32..2^40: rational reconstruction needs x_R height <= sqrt(p/2) (2^15.5..2^19.5), but relation heights are ~h^5 (>2^34). The filter is blind here (SA-05 recall 35/45 already failing at 2^40; its 2^48/2^56 runs gave 0/30000 and 0/10000 passes, reused, not recomputed). The random-target arm instead measures the direct yield: 10^5 random on-curve abscissae per prime, hit if x_R = x(P+-Q) for some base pair (streamed over all B(B-1)/2 pairs); every hit recomputed with Python bigint group addition (0 failures). Same object the filter approximates, no reconstruction needed.
2. New C++ program sumset2 (streaming, no stored sums) replaces SA-05's sumset so B ~ 5*p^(1/3) fits in memory; SA-05 finished cells were not recomputed (its data are only cited).
3. B = 5*p^(1/3) (prereg: B >= p^(1/3)), to get ~85 expected distinct generic relations per prime. Heights h = 116, 182-184, 292.
4. Relations deduplicated as unordered x-triples (each is found from 3 pairs). Generic expectation per prime = B(B-1)(B-2)/(3*p/2). Integer base: first B on-curve integers by |a|.
5. Only 3 p values (2^32, 2^36, 2^40) x 4 primes. Slope CI from bootstrap over primes.
