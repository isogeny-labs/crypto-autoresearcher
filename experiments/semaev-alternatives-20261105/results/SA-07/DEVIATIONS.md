# Deviations from the frozen SA-07 protocol

1. Host contention (load average 20-30 on 4 cores) cut the usable CPU share to a few percent per process. Per-instance SCIP limit is therefore 5 s CPU (clock type 1, one thread), seeds = 2 per cell (not 3+), and prime sizes beyond 2^28 / 2^36 may be missing or thin. Cells actually run are listed in results_table.md.
2. m = 3 uses S_4(x1,x2,x3,x_R) = Res_T(S_3(x1,x2,T), S_3(x3,x_R,T)) (the prereg text only writes S_3). Curve y^2 = x^3 + 7.
3. For each seed the prime is nextprime(2^bits + 7919*seed) (then bumped until at least 3 x <= B lift to the curve); primes therefore differ slightly per seed.
4. "LLL formulation": the lattice is {z in Z^n : sum c_lambda z_lambda = 0 mod p} over symmetric-orbit monomial sums z_lambda (6 for m=2, 35 for m=3), column-weighted by 1/box-bound and LLL-reduced with fpylll; SCIP gets integer coordinates u in the reduced basis, z = u*Basis, plus z_lambda = m_lambda(x) nonlinear constraints. The Vieta formulation branches on elementary symmetric e_k with (m=2) e1^2-4e2 = w^2.
5. SCIP works in doubles. For raw/Vieta the congruence has values up to ~2^60+, so SCIP sometimes declares false infeasibility. Every returned solution is re-verified exactly (sympy, integers); "false" in the tables = SCIP status infeasible/spurious, not a timeout.
6. Early in the run I issued a `pkill -f driver.py` (to restart my own jobs); the harness blocked the second such call, but the first may have terminated another executor's process named driver.py. Reported for transparency.
7. Because very small B (4, 8) at m=3 gives degenerate planted instances (repeated x, 1-node presolve solves), fits are reported with and without them.

## Resume phase (added 2026-11-05 by the resuming executor)

8. The run was interrupted by an API usage limit and resumed by a different model (Claude Opus 5.5) in a fresh container. The predecessor's rows (raw_m2.jsonl, raw_m3.jsonl; 264 runs, 5 s CPU cap, seeds 1-2, p ~ 2^28/32/36/40) were kept unchanged. Its fits_table.md / results_table.md predated its last 3 dozen rows and treated timeouts as point values; both tables and fig_nodes.png were regenerated by analyze2.py / analyze_quantile.py over all rows. The old analyze.py is kept for provenance but its output is superseded.
9. Resume phase (driver2.py; raw2_m2.jsonl, raw2_m3.jsonl; 180 rows): same generator and formulations (sa07.py unchanged), seeds 3-5, p ~ 2^28 and 2^36 only (not 2^32, 2^40: wall-clock budget), 20 s CPU cap, B in {16..256} (m=2) and {4..64} (m=3). Skip rule: after 2 consecutive timeouts in increasing B for one (bits, form, seed), larger B are recorded "skipped" and not run (34 rows). Skipped rows are excluded from fits, which biases fitted exponents downward (conservative for KILL).
10. Exponent estimators: the prereg says "fit exponent". Because 69% of runs time out, an OLS fit on solved runs only is a survivorship-biased estimator (it keeps only 1-node presolve hits at large B and yields negative slopes at m=3). Primary estimator is a Tobit fit (log2 nodes vs log2 B, timeouts right-censored at nodes-at-cap) with instance bootstrap; secondary is a model-free censored quantile lower bound. Both are reported along with the survivor OLS.
11. Mixed caps (5 s and 20 s) are pooled; this is valid for censored estimators (each timeout is its own lower bound) but makes the wall/CPU-time metric's lower bound equal to the smaller cap.
12. The Write tool refused REPORT.md for this subagent; per RESUME_BRIEF item 4 the full report text was returned in the final message for the main session to save. Not worked around.
