# SA-22

**Why.** Toy runs cannot reach cryptographic sizes. A cost model built from measured components can, provided every term is charged. This experiment projects total solve time for each oracle and compares it with rho at log2 N ∈ {64, 128, 192, 256}.

**Protocol.**
1. Cost model (index calculus with arity m, factor base B = p^β, oracle reach δ, oracle cost C_o(N), linear algebra on B/|Aut| columns with weight-m rows): T = (#relations ≈ B) × (attempts per relation ≈ m!·N/B^m when B ≤ p^δ, i.e. the oracle can only use B ≤ p^δ) × C_o + T_LA(B) + T_descent. Optimise β ≤ δ per oracle. Rho: √(πN/4) group additions.
2. Oracles, each with measured per-call cost taken from the campaign's raw outputs or re-timed on this host (LLL or msolve time as a function of dimension and bit size, fitted and extrapolated with a stated law): pair table (generic), Weierstrass form lattice (δ = 1/9), Edwards form lattice (δ = 1/8), Coppersmith ladders at the measured finite-t reaches (SA-01, SA-20), cuso certificates at m = 3 (1/24), msolve norm/tower presentations (SA-04, SA-14) at their measured degree laws, and Heegner free relations (SA-09c: fraction 0.13 of points related) as a relation-phase discount.
3. Price unpriced work at 0, 0.1 and 1 GAE per field operation; report the order only where it holds across the band.
4. Validate the model against SA-21's measured toy points at 20–40 bits: predicted vs measured total cost within a factor of 3 at every size, or report the discrepancy and correct the model before projecting.

**Prediction (frozen).** Every non-generic oracle's projected total cost exceeds rho by a factor that grows with N, by ≥ 2^40 at 256 bits; the generic pair table is the best IC arm and still exceeds rho.

**Criteria (frozen).**
- SUCCESS: any oracle whose projected total cost is below rho at 256 bits under every pricing, with the model validated against SA-21 within a factor of 3.
- KILL: every oracle's projected cost exceeds rho at 128 and 256 bits under every pricing, with the model validated.
- INCONCLUSIVE: otherwise (including a model that fails validation).
