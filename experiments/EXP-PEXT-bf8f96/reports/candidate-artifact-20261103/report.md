# EXP-PEXT-bf8f96: bounded candidate artifact helper

The [artifact helper](../../implementation/candidate_unit_artifact.py) now creates an exclusive directory for one candidate unit. It records the exact field/form/caps, binary digest, and, for an approved cohort, the selected class/T binding. A successful child output is checked for field, form, structure order and coverage identity, then stored as deterministic gzip with raw and compressed SHA-256 digests. A nonzero exit, watchdog timeout or invalid output retains its partial stdout, stderr and a write-once failure record. No failed directory is reused.

Production construction checks an existing frozen trial plan through `experiment_execution.load_plan` and the live dispatcher claim through `authorize`. It requires the bound candidate source closure and published input, manifest and join-plan hashes in that plan. The supervisor remains responsible for the whole trial's launch, resource cap, claim expiry and execution receipt; this helper is one component inside that path. A checked cohort plan and live claim do not yet exist for this experiment, so the production constructor has not been invoked.

The fixed F27 [software tests](software-tests.json) compiled the Rust candidate and join fixture tools. One unit emitted a compressed artifact and independently replayed all 279 exceptional ordinals. A second unit was forced to exceed its candidate cap and retained a failure record, partial stdout and stderr. Tests also rejected duplicate output directories, nonpositive caps, a memory ceiling above 4 GiB, a changed binary digest and direct construction of a production-scoped helper. Five tests across the binding and artifact modules pass. These are software checks, not scientific cohort trials.
