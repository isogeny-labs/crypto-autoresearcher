Classical ECDLP: fixed-arena endpoint reuse implementation

This is implementation and software-conformance development. No scientific
confirmation cohort or comparative benchmark was executed here. A subsequent
experiment must use its frozen public inputs and authorized isolated backend.
No measured clocks or L2 qualification are emitted by this program.

Build:
  python3 build.py --output /tmp/endpoint_reuse
  /tmp/endpoint_reuse --self-test
For forced collision/rollback development controls, add --development when
building. --sanitize adds ASan/UBSan; this host uses ASAN_OPTIONS=detect_leaks=0.
Production builds omit the development-only table mutation APIs.

Run interface:
  endpoint_reuse --run FIXTURES.tsv PUBLIC_TARGETS.tsv SETTINGS.tsv ARM FRESH.jsonl
Exact TSV columns, row fields and counter definitions are in SCHEMA.json.
An existing output is refused. Target files contain only public points, curve
and replicate identifiers, and public target ordinals. No scalar-label column
is accepted. A cell resets the table and processes its own replicate in the
input order. The five original arm names and the sixth control are:

  static_small: unchanged upstream BL with initial_chains raw terminations.
  static_full: unchanged upstream BL with endpoint_cap raw terminations.
  harvest: initial small BL, then verified-only endpoint reuse up to the cap.
  harvest_disabled: same initial small table, with reuse disabled; A/A control.
  static_filled: same initial small table, then dedicated known-scalar walks
                 until C DISTINCT endpoints or an explicit watchdog outcome.
                 Its target solving uses the unchanged disabled const path.
  rho_reference: actual upstream negation-map rho, threads=1, paired public seed.

All BL arms use the same fixed r=20 adding-point count, public dp_bits, seed,
threads=1, walks=1 and early_abort=0. This differs deliberately from the older
validation's automatic batch width. Width one prevents raw endpoint-count
overshoot. Every BL arm reserves the same C-slot endpoint arena after initial
construction. C0 and C are prospective settings, not posthoc occupancies.
Raw terminations need not be distinct: static_full is a full REQUEST-BUDGET
control, whereas static_filled really has C distinct endpoints when ready.
A censored fill keeps its actual partial table, witnesses and hash.

Pinned baseline:
The 13 vendor files are byte-identical to cryptanalysis commit
379faa0f1e38facd9c8fdfc527f0b89518cf2e70; vendor-source.json is checked at build.
baseline_inspection.c textually includes the pinned precomp.c unchanged and
adds storage-reservation and read-only inspection helpers. RNG wrappers count
the same pinned xoshiro/Lemire semantics; deterministic stream tests include
rejection-prone bounds. candidate/endpoint_reuse.c is an independent derived
fork generated by derive_candidate.py. The original vendor is never rewritten.
This implementation is related to the repository's existing advice-table
variants; novelty and prior-evidence interpretation are separate records.

Correctness invariant:
Each online walk maintains Y=Q+aP. A terminal D is recorded with its actual
point, fingerprint, offset a and terminal reason. While x is unknown, a pending
(fp,a) pair occupies an UNUSED slot of the same arena; the known prefix length
nent never changes, and lookup uses only indices below nent. After xP=Q has
been publicly checked, e=(x+a) mod r is a known exponent for D. Because P has
verified prime order r, eP=e'P iff e=e' mod r. Canonical exponent comparison is
therefore exact full-point deduplication, without storing extra point objects.
Duplicate pending observations can consume available slots before the witness
is known; dropped observations and duplicate counts are retained.

The enabled lookup scans a complete matching-fingerprint bucket and publicly
checks every scalar witness. The unchanged disabled path keeps upstream lookup
semantics. Distinct points sharing a fingerprint therefore cannot poison a
returned answer. The initial upstream table retains its historical
fingerprint-only deduplication; this limitation is explicit.

A verified_solution event precedes all activation proposals. Proposals and a
commit-ready event are intentions until the final target row reports
harvest_committed=true. Failed targets discard pending slots. Streaming errors
before activation do not change known entries. Candidate checkpoints are
unsupported; they are refused instead of silently omitting new state.

Fixed memory:
Known entries and pending offsets share exactly C pairs of (uint64,uint64).
No full-point trail or endpoint pool is retained outside that arena. Full D/a
records stream to JSONL. Growth and distinct-fill sorting use in-place heapsort
with a single extra entry as constant stack workspace, and sorting is skipped
when no endpoint was inserted. Initial upstream construction still has its
worker buffer and collection allocation, and may use library-sort scratch.
These requested payloads and the object/fixed-base/adding arrays are reported
separately. Allocator metadata, pthread stacks and actual process RSS are not
inferred from table payload; the parent runner must record observed max RSS.

Work accounting:
counters.group_additions counts each shared Ops.add call once, including
calls implementing doubling or involving identity. Scalar calls and field
operations are nested diagnostics and MUST NOT be added to that count.
Complete method group work is setup plus all target deltas. Common input
validation has its own row. Insertion scalar arithmetic, exact comparisons,
sorting, upstream RNG words/requests and adapter hashes are separate counters;
a group-work comparison is not an assertion that those costs vanish or a
measurement of total runtime. Raw output and audit digests are recording work.
The parent captures whole-child CPU/wall/RSS separately with actual isolation.

Reported precomputation watchdog:
The upstream max_precomp_ops bounds its build WALK counter, excluding the
fixed adding table/Gpow setup. To bound total REPORTED initial+fill work,
this wrapper subtracts B=21*(bitlen(r)-1) before calling the upstream builder.
Gpow takes bitlen-1 doublings. Each of 20 nonzero adding scalars takes at most
bitlen-1 additions of Gpow entries, proving B. A nonzero total limit <=B
censors before construction. Fill charges the actual initial reported total
and checks remaining budget before every new group operation. Its independent
start bound is max_precomp_ops+C+64 (uint64 overflow is rejected), so zero-work
starts cannot loop indefinitely even when the group-work limit is zero.
Actual Ops.add counts include checks absent from the upstream reported counter;
they are not falsely claimed bounded by this reported-work watchdog.

Dedicated static fill uses the same S and DP map. Its independent start RNG
seed is settings.seed XOR 0x65722d66696c6c31. Every start is a known aP and each
step adds its known s_i. Initial construction, fill walks, starts, duplicates,
comparisons, sorting and final verification are all retained. No hidden target
label or current/future Q is consumed by fill.

Arithmetic range:
The exact legacy public Ops/validator is retained: p<=1048575, r<=524287,
ordinary nonspecial non-anomalous inputs, checked prime r and nonidentity P of
order r. No larger-field support or silent guard extension is asserted.

A/A conformance compares canonical status/answer, exact initial/remaining
endpoint bytes, complete EC/auxiliary/RNG vectors and upstream deterministic
work. Arm labels, observation metadata and the larger candidate bookkeeping
object are not falsely claimed byte-identical. Fixed development fixtures and
hand-selected public scalars are software tests, not confirmation samples.
