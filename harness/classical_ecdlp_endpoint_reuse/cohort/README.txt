Prospective endpoint-reuse cohort inputs
======================================

Status: SOURCE AND DETERMINISTIC SOFTWARE CHECKS ONLY.
No new confirmation curve panel, private OS seed, target label or solver
measurement has been generated by this development task.

Fixed design
------------
64 fresh ordinary non-anomalous curves: 16 each with prime subgroup order
of 12, 14, 16 and 18 bits. Coefficients a,b are nonzero and the discriminant
is nonzero (j is neither 0 nor 1728). The cofactor is 1, 2 or 3, coprime to r.
Each curve has two independent setup/target-seed replicates, each with 64
uniform-with-replacement scalar draws: 128 cells and 8192 public target IDs.

The 114 excluded coordinate-model curves are the union of the prior 32,
last-study 48 and development 34; the latter already includes the 24
superseded-preparation curves. Five immutable source copies retain their
overlap and published commit/path/SHA-256 provenance. Exclusion uses (p,a,b),
which is stronger than refusing a repeated generator/subgroup on that model.
This is representation freshness, not an isomorphism-class exclusion.
Historical metadata are retained without inventing historical EC1 labels.
New certified fixtures receive exact EC1 aliases and full curve UIDs through
the byte-identical repository curve_identity.py helper.

Entry points
------------
prepare.py generate --repo-root REPO --source-lock LOCK.json \
  --lock-commit REAL_COMMIT --protocol-sha256 FROZEN_CANONICAL_SHA \
  --nonce EXTERNAL_NONCE.json --out NEW_PREPARATION_DIRECTORY

prepare.py check-lock uses the same required binding arguments but creates
no cohort or private entropy.

prepare.py assemble-targets --manifest public/public-targets-manifest.json \
  --out NEW_RUNTIME_TARGETS.tsv

The generator verifies committed source bytes, committed frozen
experiment.protocol/v1 bytes, the committed lock itself, ancestry, declared
chronology and exact canonical protocol hash. It then runs the unchanged
official protocol validator/schema from the source commit. Missing or
mismatched inputs are refused before output creation or private entropy.
These checks do not grant experiment approval, ownership, queue access,
external timestamp attestation, or a scientific result.

Only the top-level Python custodian is a cohort entry point. The C++ helper
performs deterministic public fixture search and contains no target-seed or
private-label functionality. Calling the helper directly is not an admitted
cohort preparation or experiment route.

Seed rules and confidentiality
------------------------------
Public setup/order seed:
SHA256(b"classical.ecdlp.endpoint-reuse.v1\\0" +
  protocol_sha256_ascii + b"\\0" + nonce_ascii + b"\\0" +
  fixture_id_ascii + b"\\0" + replicate_decimal_ascii + b"\\0" + purpose_ascii),
first eight digest bytes interpreted BIG endian. SETTINGS.seed uses purpose
solver_cell. The order helper uses arm_order. The public fixture sampler
uses fixture_id=cohort, replicate=0, purpose=curve_generation.

Target scalar seeds DO NOT derive from the public nonce/protocol alone.
Only after all gates and a public fixture seal does the custodian draw a
private 32-byte OS root. For each fixture/replicate it uses HMAC-SHA256 with
that root and the source-fixed endpoint-target-sampling.v1 NUL-separated
domain, protocol hash, public nonce, fixture ID, replicate and uint64BE
counter. Exact 256-bit rejection followed by mod r removes range-reduction
bias. The private root record is hashed into a public pre-target commitment.
Labels and root remain in private/ and are not solver inputs. This is a
source/process-interface convention, not OS-isolated blindness.

Public fixture certificates compare the C++ root-multiplicity census,
separate C++ Euler census and independent Python Euler census. Python affine
arithmetic verifies generator order and every Q's prime-subgroup membership.
Q generation uses separate Jacobian arithmetic; every private kP equation
is checked against the affine implementation before it is written.

Public interfaces
-----------------
fixtures.tsv:
fixture_id stratum p a b gx gy r N seed   (TAB-separated; N=h*r)

targets-<fixture_id>.tsv:
fixture_id replicate target_id target_ordinal qx qy infinity
One part per curve: 128 rows, replicates 0/1 and ordinals 0..63.

settings.tsv:
cell_id fixture_id replicate dp_bits initial_chains endpoint_cap
max_precomp_ops max_online_ops seed

Let t=bit_length(r)//3, C0=(r+2^(2t)/2)//2^(2t), C=4*C0.
Operational watchdogs are max_precomp_ops=256*C*2^t+8192 (upstream
reported build group operations per cell), and
max_online_ops=256*ceil(sqrt(r))+8192 (upstream reported group operations
per target). These are not full-method work counters or mathematical
failure criteria. Initial/full chain requests may deduplicate to fewer
stored endpoints; no capacity retuning or structural NA follows from that.

All TSV/JSONL public parts are at most 60 KiB. JSON metadata stay below
1 MiB. The target manifest binds each part and the canonical merged TSV,
with one header and part bodies in manifest order. The combined TSV is a
runtime reconstruction, not an unpartitioned Git artifact.

inputs-manifest.json hashes every public file except itself. Its own
SHA-256 must come from the admitted execution plan. public_inputs.py:

  cohort = load_inputs(Path(public_root), expected_manifest_sha256)
  files = write_cell(cohort, cell_id, Path(fresh_runtime_directory))

The reader rejects undeclared files, altered hashes/headers, missing or
duplicate cells/targets, wrong seed/settings laws, invalid curve/subgroup
points and noncontiguous target order. It never reads private/. A cell
slice contains exactly one fixture, one settings row and 64 public Qs.

Validation and runtime estimate
-------------------------------
Development checks use only four fixed hand-selected curves over p
17,37,61,127 and fixed public test key bytes. They test software conformance,
not the prospective 64-curve study or a performance comparison.

No new preparation timing was collected. Analytically, certification
requires three complete field-point counts per accepted curve (two C++
forms, one Python Euler form), plus point searches and scalar checks.
The largest sampled p is below 2^19, so the independent Python count scans
at most 64*2^19 field x values; expected rejects add C++ search work.
The one-million-candidate operational search limit is source-fixed and its
full accept/reject history is retained. Exhaustion is input-preparation
incompletion, not evidence about the endpoint-reuse algorithm.

The previous 48-curve preparation source and its immutable history are
pinned in exclusions/manifest.json; that prior preparation is a context
pointer, not a measurement of this new source.
