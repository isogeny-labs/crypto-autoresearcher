## Question and matched panel

Test whether randomized public arithmetic-progression sources preserve useful
base information and natural-target recovery while reducing complete cold
construction cost relative to optimized hashed sources. AP correlations may
reduce independent equations or target recovery. Retain that outcome, every
failed attempt and all adverse costs. AP walks, fixed-base tables and row-space
membership are established methods; there is no novelty or expected speedup
claim.

The intended finite panel is four fresh curves: two at p=8191 with 16 base
atoms and two at p=65537 with 32. Draw eight fresh canonical-y public targets
per curve without scalar labels. Pair AP and hash seeds 0, 1, 2, each with 128
sources. Retain budgets 0/8/16/24/32/48/64/96/128, both relation-only and explicit
known-point-anchor scopes, and both kernel-free solvers, with actual IDs `sparse_joint` and `sparse_cancel`.
Thus there are 432 dependent row systems and 864 cold solver evaluations.
Prefixes, scopes, seeds and solvers reuse four curves and 32 target points;
they are not 432 independent draws.

Use one signed pair table and one target-query stream per curve. The intended
physical totals are 147,456 source queries, 1,536 target queries and 4,928 pair
entries. A separate finite signed-triple oracle enumerates 88,320 triples once
over the four curves, mapping their sums to every source/target query. Do not
report an equivalent repeated enumeration as actual physical checker work.
These counts describe the prospective panel, not observations.

## Source streams and actual constructors

For each AP seed, derive nonzero a,d modulo the prime order r and use
`s_i=(a+i*d) mod r`, i=0,...,127. A nonzero d and r>128 ensure distinct scalars.
A prospective rule may reject an entire parameter candidate if the declared
128-term horizon contains zero; all such rejections and derivation costs stay
in the trace. Do not reject opposite points, base/target coincidences, low
relation yield or poor rank. The final source must fix the exact candidate and
counter recipe rather than rely on this prose.

Compute A=[a]P and D=[d]P with the selected charged constructor, then walk
`Q_0=A`, `Q_(i+1)=Q_i+D`. At full budget the walk uses 127 additions after its
starting constructions. Incremental budgets construct only their new walk
segment. AP's known public step D is real information even if it is not a
queried source point.

The paired hash stream draws 128 distinct nonzero public scalars with its own
frozen hash recipe, retaining all candidates and duplicate rejections. Source
scalar labels are public and permitted; target labels remain unknown.

Use the actual existing FixedBaseMultiplier implementation for positional
windows 1..8 plus the binary constructor control. An adapter must route the
actual group operations through the same Fp instrument as the collector, so
switching engines does not drop field counters. Both AP starts and hash sources
receive applicable constructor optimizations and the same declared prerequisite
cache policy. Do not force a two-point AP workload to buy an unnecessary
hash-sized table, or compare a walk against repeated unoptimized binary calls.

Select the constructor by a fixed scalar-only prediction rule with cold setup
included; freeze its objective and tie-break. It may inspect public scalar digit
patterns and declared cache keys, not measured Fp timing, table/base/target
coincidences, rank or recovered targets. A minimum predicted group-call count
within binary/windows1..8 is not a claim of globally minimum Fp/Fr/CPU cost or
optimality among unimplemented methods. The implemented selector runs nine scalar-only simulations: binary is window
0, followed by positional windows 1..8. Each models the full declared workload,
including setup and dynamic exact-scalar cache discovery. Minimize exact group-add
API calls, breaking ties by binary first and then ascending window. Retain all
nine predictions, simulated-add counts, policy CPU and selected-plan justification.
Only the selected EC constructor physically runs: these are not nine EC
construction controls, nor nine measured Fp vectors. Software controls may
exercise alternative real constructors on marked tiny fixtures separately.

The actual prediction workload is all 128 public hash labels or AP's two labels
[a,d]. This is prepaid scalar-only full-horizon policy work; its chosen window
need not be best for stopping at eight sources. Setup is lazy: only the first
uncached top-level request initializes the selected table, at the first positive
budget that needs it. Budget zero receives only the shared prerequisite points
1..64, not future arm table/intermediate anchors. A fully cached workload needs
no selected EC table even when its candidate window is nonzero.

The dynamic exact-scalar cache includes prerequisite and discovered intermediate
labels and is consulted for top-level scalar requests. An internal add still
executes and is charged even if its result was already known. Negated points are
not cached for scalar reuse. These details are common to prediction and actual
construction and must agree with the independent replay.

## Labelled intermediate points and prefix knowledge

Every point computed with a known scalar label can reveal information. Record
labelled table entries, doubling/addition intermediates, AP starts/step and walk
points, with normalized scalar, point and first-available budget. Identity and
sign coincidences require consistent labels. Meter recording, comparisons,
anchor scans and retained storage rather than calling them free.

A source schedule's operational knowledge at budget b consists of the declared
shared prerequisite plus points its selected constructor/stream has actually
made available by b. Other schedules, future points and labels appearing only in alternative
scalar-only simulations do not enter that prefix's solver inputs. Only the chosen
constructor creates EC points in this panel. Each available point is also
negated, scanned against base atoms/targets and charged; the sign scan does not
create a reusable negative-point scalar cache. Source-query and relation-check
intermediates are outside this declared labelled-constructor knowledge boundary.
This is an explicit operational/cost boundary, not secrecy of public recipes or
a claim of full closure under every other feasible public computation. Retain
that limitation when interpreting either anchor scope or constructor selection.

The `relations` scope uses scheduled relation rows and the fixed original
projection. The `anchors` scope also receives known base-point equations
from all declared available labelled points, as rows in the same columns. Never
silently lower U or treat a new anchor as new relation rank. In the actual `anchors` scope, available constructor target matches also become
explicit target equations: base vector zero, target coefficient -1 and RHS
`-known_scalar mod r`. Deduplicate these by target within each prefix after
filtering first availability; no checker-recovered label is a solver input.
These equations can identify a target without any natural decomposition and
must remain distinguishable from collected target rows and cancellation gains.
The `relations` scope contains only natural collected target rows. Retain
construction-only public certificates/diagnostics, known base anchors and genuine
multirow information separately. All targets and coincidences are retained
regardless of success.

## Kernel-free solvers with full certificates

Both solvers use sparse certified elimination with the same field operations,
row order and pivot policy where applicable. The joint solver inserts the
original source rows and eight target columns. The cancellation solver freshly
constructs one same-target difference for each additional target row, inserts
M plus those differences in the original U columns, and tests target
representatives. No saved old cancellation matrix or target scalar is an input.

For a consistent affine system, reducing a queried vector to zero is precisely
row-space membership. Its carried weights yield the scalar/value certificate.
Use that test in both solvers without building a full production right kernel
or evaluating vN to duplicate the same decision. Retain nonzero residuals and
the certified echelon system for negative results. Missing target groups remain
unidentifiable. An independent dense implementation checks rank/nonmembership,
consistency and every positive original-row coefficient/RHS certificate.

Cancellation weights must be lifted to the original joint rows, and all
identified scalars must pass independent public [k]P=Q checks. Keep lifting and
original-row/public verification costs; they can outweigh cheaper elimination.
If self-contained negative dual witnesses are requested, construct and charge
them explicitly. Complete kernels computed by a checker are separately labelled
checker work; A10 does not alter old A9 complete-kernel promises.
