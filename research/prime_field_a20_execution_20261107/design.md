# Prospective formal-versus-numeric auxiliary information

The question is whether a paid signed-pair dictionary improves finite useful
information and actual target functionals relative to coordinate-hashed unknown
points, without supplying numeric helper logarithms. It is a comparison of
programs using existing group sums and linear relations, not a novel symmetry,
isogeny, generic-curve oracle or exponent claim. Zero/adverse outcomes are kept. [pcc:unverified]

All four cold arms have the same old norm32, common prerequisite64 projection,
AP0 source128, new public target points and GENERAL8 recipe. Every source and
target slot runs, including equations involving already recovered targets.
Common M contains only norm source-query decompositions under that projection;
each own source-query stream must contain it. No private source anchors,
helper units, formal definitions or target construction enter M.

For index/counter, SHA256(domain|formal-pair|full EC1 UID|index|counter) is split
into two distinct old native indices and two signs. The resulting signed sum
is canonically oriented and its old coefficient vector receives the same sign.
The first finite non-old/nonprevious sign class is accepted, at most10000
candidates per point,16 accepted points. Old public subgroup/sign setup,
candidate hashes/additions/negations/comparisons/rejections, definition
coefficients and payload storage are charged. No complete pair table is reused;
the later native index is another actual owned build and remains charged.

One accepted definition is inserted per auxiliary, after declared common units
and before own cache/source/anchor rows. Its auxiliary block is identity, so the
definition-only block adds zero old-base information. This is conditional on
the distinct/non-old/one-definition boundary. Old-point collisions or multiple
definitions for one point could otherwise reveal an old-base relation without
numeric logs. The first test explicitly does not harvest rejected collisions;
their traces and costs are retained but never feed source/target constructors
or matrix rows. A symmetric collision-harvesting programme is separate work.

Formal coefficient vectors are never numeric P labels. Preparations reconstruct
initial numeric caches solely from actual prerequisite/helper constructors.
Later legitimate own source/P-constructor coincidences remain explicit K
equations, even when they make K informative. Known16 uses another public point
set with its actual numeric constructor/cache; this is not a same-point
intervention revealing formal or coordinate-hash pool logs.

The native width is32 or48, requested target count8, joint width at most56
under the unchanged64 guard. New definition rows count toward the same4096
row cap. Auxiliary-first recovery and independent full native joint controls
run on exactly the same own pools, retaining target units, negative residuals,
original weights and public scalar checks. All existing information views
cancel **both** auxiliary and target U, using actual rank(U):

    Delta = rank([[M,0],[B,U]]) - rank(U) - rank(M).

K_source includes definitions plus own supplied/constructor source equations;
K_full additionally includes actual pure-P Registry base matches. Report their
cancelled contribution, collected increment conditional on K, source/full
marginal and direct/cross-row gains. K need not be zero even though definitions
alone pass the zero-information control. All native weights, complete left
kernels, independent dense ranks and old-kernel action remain retained.

The independent expanded-old oracle directly reconstructs every accepted point
from its signed components, checks canonical/non-old/nonduplicate classes and
the native public point, then expands each complete source/target row onto old
native coordinates. It keeps coefficient sums modulo the subgroup order;
three formal pair atoms can contribute six old occurrences with repetitions.
It verifies each expanded point equation, affine consistency, native rank minus
auxiliary count, requested-unit membership and old-base rank after cancelling
targets/common units. This can merely implement higher-arity generic old-base
sums. Its independently measured checker CPU remains separate; no extra
production target solver or uncharged certificate oracle is inferred. [pcc:unverified]

Costs retain actual pool/helper/prelude/source/recipe/index/constructor/query,
definition/matrix assembly, substitution/cancellation/elimination, membership,
native lifting/public checks, allocation and storage. Both actual endpoint
engines run; independently reconstructed per-stage/aggregate records reconcile
to namespaces used by conditional single-engine costs. Native joint controls,
information diagnostics, expanded/public/dense checkers and curve generation
remain separately paid. Fp/Fr/logical/bytes are separate, no byte-as-operation,
weighted runtime or complete-S claim. Missing accounting remains explicit.

The prospective sixteen-case/thirty-two-call panel retains every bad, zero,
lost-target or failed prefix. It cannot redraw fixtures or enlarge pool/horizon
to force a favorable answer. Original resource bounds and exact prospective
source/protocol/release/normal admission still apply; this design allocates none.
