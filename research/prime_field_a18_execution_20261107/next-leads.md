supplied logarithms, alongside unchanged norm32 and a separately paid known16
helper control. The question is whether the unknown pool supplies additional
**old-base information after cancellation**, or useful independently selected
target coordinates, at its actual charged costs. This returns to the original
factor-base question without treating extra columns as information.

## Cancellation, target API and certificates

The current eight-target API is **not** a sixteen-auxiliary-point API. A new
implementation must explicitly distinguish:

- old norm unknown coordinates;
- up to16 remaining auxiliary pool coordinates after legitimate aliases/known
  equations, with signed canonical native maps;
- the eight independently chosen requested target coordinates.

The native factor-base slot count is48 and there are eight target coordinates,
within the existing joint64 guard. Keep pair8192/rows4096/labels8192 and a
prospectively derived horizon8 cache bound. Any source/API/cap change requires
exact prospective assessment; no current source is approved by this note.

For relation block [B U], let U include **both** every unknown auxiliary pool
column and every actual target column when measuring old-base information:

    Delta = rank([[M,0],[B,U]]) - rank(U) - rank(M).

Apply the same formula over M+K_arm for the collected increment and report the
supplied K contribution separately. Also retain the source-only auxiliary
cancellation result before target rows, and the marginal contribution after
adding the frozen target stream. Raw augmented rank, number of auxiliary columns,
or pool size is never base gain. Record direct base-only gain and genuine
cross-row cancellation gain where meaningful, with full row weights, cancelled
U action and action on the old M kernel. Independent dense ranks and original
public point equations must check all claims.

For each requested target, test its **actual target-coordinate unit functional**
in the complete native row space, with all auxiliary coordinates present.
Retain negative residuals and positive original-row certificates/public scalar
checks, including recovery while the old base remains rank-deficient. Do not
demand full base rank first, confuse auxiliary pivots with requested targets,
or count only target-column rank. The A18 rank4/zero-unit example is the reason
to publish named masks and unit membership alongside ranks. No target scalar
label from a checker may enter the producer.

Run the full frozen source/target query census in every arm. A17/A18's certified
target suppression is safe for supplied-known bases; it is not automatically
safe here, since a row involving an already known target can still teach old
base logs and unlock other targets. Cancellation and direct/native joint
controls must operate on the same final own rows, with independent complete
sum/pair/query/miss/geometry/affine-rank/certificate checks and failed prefixes.
