## Ranked question and scope

Compare consecutive translations, hashed offsets and general randomized affine
targets at identical target-query budgets, while preserving both AP and optimized
hash source baselines. The question is which supplied target program yields
base information and identifiable natural target functionals at its complete
retained cold cost. More queries, larger target-column rank or direct public
collisions must not be called a structural improvement.

The production solver already uses aP+bQ with charged fixed-base P/Q tables;
PKM2016 Algorithm 1 uses the same established construction. A11 adds the general
program now rather than reserving it for a favorable later comparison. The study
is a finite comparison of specified relation/target programs, not a globally
strongest ECDLP attack, a new symmetry or a novelty claim. Original Dickson,
Prym and outside-point leads remain linked in A10/next-leads.md; this priority
is not a closure or scientific-state transition.

## Target programs and construction

All three programs start at index 0 with alpha=0,beta=1, hence R0=Q. For the
other seven indices:

- walk: Rj=Q+[j]P, constructed incrementally by adding P;
- hashedoffset: Rj=Q+[rho_j]P, with frozen public offset recipe;
- general: Rj=[alpha_j]P+[beta_j]Q, alpha in0..r-1 and beta in1..r-1.

The final source must fix candidate gates and whether repeated public coefficient
pairs are retained or rejected solely as duplicate labels. Different coefficients
that yield the same actual point, an identity, a base/source point or another
target must not be rejected by inspecting that outcome. No success redraw or
checker-derived scalar is allowed. Hash tags bind full EC1 curve identity and
target index; all source/target policy seeds and candidate traces are fixed.

Optimize source and target P/Q scalar branches using the actual binary and
FixedBaseMultiplier windows 1..8 portfolio. The target selector models uncached
EC additions using public scalar labels only, with deterministic ascending-window
ties (binary is window 0). Reuse an already known coefficient-sum point before
performing an EC add, while charging wrapper calls, metadata, lookups and storage.
This differs from merely counting every add API call as a fresh EC operation.
Nine scalar simulations are policy CPU/logical work, not nine executed EC
constructors. Measured Fp costs, rank or point coincidences cannot select a plan.

Target construction is cold separately for each source schedule, source prefix
64/128 and target policy. Its P cache starts only from that source branch's paid
positive/negative known points available at that prefix. Share its P table across
the eight targets within that branch/policy; Q multiplier caches remain symbolic
lambda*Q caches for their own target, never secret-q scalar tables. This is a
many-target scope, not a claim of cold single-target optimality. Record separate
P/Q selection, setup, hits, wrappers, metadata and actual EC work. A full-horizon
choice need not be best at target budget 1, and lazy setup/first availability
must preserve the declared target budget boundary.

A global decomposition cache is distinct from these constructor knowledge caches.
The j0 natural stream seeds it; the same physical endpoint is queried once across
source branches/policies. Retain every endpoint request and alias. Cold-arm
primitive query views may refer to the retained deterministic point-query counter
record, clearly labelled as cost references rather than actual reexecutions or
independent clocks. Global cache contents must not leak another branch's symbolic
labels or paid known-point equations into the chosen branch's algebra.

## Affine labels, collisions and available knowledge

A point involving Q has a symbolic affine label, not a known public scalar.
General Q-table entries [b]Q and all intermediate sums carry target coefficients
and offsets. They must never enter the known-scalar source cache with a fabricated
q. Multiple symbolic labels on the same actual point are legitimate public
affine relations, not an inconsistent-known-scalar error or grounds for redraw.
Keep each chosen program's knowledge limited to its paid source prefix and
target budget. Other programs, future tables and recovered solver/checker values
cannot leak into that system. This is a declared operational boundary, not secrecy
of public recipes or full closure under all public computations.

Prospectively state which identities and signed coincidences become paid rows
and which remain diagnostics. If alphaP+betaQ=[k]P, retain beta*q=k-alpha. If the
point is identity, retain beta*q=-alpha. Equal/opposite affine points can yield
one-target or cross-target equations, sometimes without a natural decomposition.
Preserve those equations and costs with separate origins; never mislabel them
as ordinary collected decompositions or individual known scalars. Global point
aliases must preserve every requested target/program/coefficient identity.

The fixed original projected base columns remain unchanged across all policies.
The relations scope uses the declared source/target relation stream and fixed
projection. The anchors scope also receives the explicitly declared available
known-base and affine-target equations. New public information is inserted as
rows, never silently as deleted unknown columns. Direct public recoveries,
construction-derived anchors and genuine cross-row information remain separate.

## Raw equations, cancellation and certificates

If a signed decomposition of alphaP+betaQ gives base coefficients with known
contribution k, its original projected equation is
`[v,-beta*e_t]*(z,q)=alpha-k (mod r)`.
Retain this original row, alpha/beta, target identity, signs and public group
certificate. There are at most the same eight target unknowns; do not introduce
an unrelated unknown for every affine point or table entry.

The joint baseline inserts raw U rows directly, including -beta and arbitrary
multi-target public coincidence vectors. Cancellation must therefore eliminate
general outside columns, not assume every row has one -1 target coefficient.
Reduce U rows while carrying their base coefficients, RHS and weights on the
original raw target rows. Outside-dependent rows yield C=Lambda*B and d=Lambda*b
with Lambda*U=0; insert M plus C in the original base columns. Normalize outside
pivots with paid inversions/scaling, using unit shortcuts where actually
implemented. Do not force the joint solver to pay redundant preprocessing.

For target t, first reduce the outside unit functional e_t through the outside
pivots. If no lambda satisfies lambda*U=e_t, it remains unidentifiable. Otherwise
lambda*B*z+q_t=lambda*b. Test lambda*B against the certified base system M+C;
if its value is v, then q_t=lambda*b-v. Carry all outside/base elimination and
normalization weights back to the original M and raw [B,U] rows. Every positive
recovery must reproduce a unit target column, zero base coefficients, the claimed
RHS and public [k]P=Q. Missing beta factors, wrong offsets or certificates valid
only on a normalized intermediate matrix must refuse.

Both solvers use sparse certified echelon reduction and negative residuals,
without a production full right kernel. Independent dense checks reconstruct
outside/base ranks, affine consistency, nonmembership and complete original-row
weights. Missing target groups remain explicit. Every partial target row is
retained, even when individually nonidentifiable. Test target functionals before
requiring full base rank. Score
`Delta=rank([[M,0],[B,U]])-rank(U)-rank(M)`.
Target-column rank or a larger augmented system is not additional base information.
