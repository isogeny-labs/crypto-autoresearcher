# Reconstruction and fencing proof obligations

1. Induct on observation index. Base R_0 is exact. Disjoint validated D,A,U modify exactly the names whose values/membership differ; unchanged names retain their previous values. Therefore reconstructed R_i equals the actual observed map. Establish raw-output reconstruction separately; map equality is weaker than byte equality.
2. Git object identity is used under the existing content-addressed custody assumption, not as an unconditional cryptographic injectivity theorem. Equal claims-directory tree IDs imply the same observed filenames/modes/blob IDs for native parsing. Exact object availability and ordinary hash checks remain prerequisites. For every distinct claims tree, a representative retains all native claims/releases visible under that tree. Explicit fetched/worktree commits remain included even if redundant. An absent subtree contributes no claims; a failed lookup cannot enter that class.
3. The native fence takes the highest observed epoch and checks conflicts across parsed records. Repeating a byte-identical set cannot change that decision. Thus replacing repeated identical claim trees by one representative preserves the fence's result, provided its parser depends only on those paths/content and no skipped commit-specific fact. Audit this last premise against actual frozen fence source; the derivation does not waive ancestry checks for publication bindings.
4. Actual timestamp order is unchanged by compression. Observation selection uses actual completion, not serialization time or a heartbeat. An observation that finishes after readiness cannot be moved before it. Store monotonic and wall times with exact meaning; neither supports a fabricated earlier reconciliation.
5. Byte-budget refusal is monotone: once appending a fully encoded record would cross its allocation, no write occurs and reserved failure custody remains available. Prove all writers share the same accounting/serialization lock and count all physical retained copies. A digest reference saves space only when its target blob is actually retained and counted once.
6. Independent reviewer must seek counterexamples: deleted/readded refs, moved refs with unchanged claims trees, changed claims bytes, identical epoch with conflicting records, absent vs error subtree, duplicate keys, corrupted/missing chain blob, interleaved write race, same-second completion order and worst-case full churn. This is a written review, not executable replay or a new validation slot.

## Discharged scope and remaining implementation obligations

Independent source inspection confirms that native fence groups exact paths/content by basename, rejects conflicting bytes, includes local claims and selects highest epoch; it does not inspect containing-commit ancestry within fence. Representative reduction therefore preserves these parsed-record decisions under the explicit conditions in specification-v2.md. Full runtime success is not equated: deadlines, command failures, output limits and time predicates remain separate gates.

The delta induction is a mathematical property of validated observations. A future writer still needs independently reviewed handling of partial writes, locking, file/directory fsync, all historical retained bytes and a bounded failure record. This packet supplies no implementation or empirical assurance of those properties. Record category overlaps explicitly; conservative double-counting is allowed, uncounted physical bytes are not.
