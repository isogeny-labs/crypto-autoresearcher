# Lossless ref-delta custody — design only

Scope: represent actual root ref/claim-tree observations without changing the frozen native fencing semantics. No helper execution, mapping replay, manifest generation, candidate/oracle import, unit, metadata retry or increased cap is authorized.

Let R_i be a finite map from exact ref name to immutable commit object ID at observation i. Let C_i map each distinct observed commit to its exact native claims-directory tree ID or an explicit ABSENT tag. ERROR is never ABSENT and makes that observation unusable. Record the repository object format; this checkout's native consumers require40hex commit IDs. Reject a format mismatch rather than truncating IDs. All named refs, including names that sort unusually, remain distinct UTF-8 strings under the recorded canonical encoding. Do not silently normalize names.

Store one canonical full R_0. For each later observation store three disjoint maps/sets: deleted names D_i, added name/value map A_i, and changed name/value map U_i. Deletions must exist in R_(i-1); additions must not; changes must exist and differ. Reconstruction deletes D_i and overwrites/inserts U_i,A_i. Reject duplicate JSON keys, repeated names, conflicting categories, missing sequence links and noncanonical ordering. Store both previous and resulting canonical mapping digests and counts. These digests bind identity, not proof of truthful observation; actual native command receipts remain necessary.

Store a content-addressed table of commit→claims-tree results once per distinct commit, including explicit ABSENT results and actual observation provenance. Preserve original complete observations. A reused result is valid only for the same immutable commit object; a moved ref requires resolving its new commit. Choose one deterministic representative commit per non-ABSENT tree plus mandatory fetched/worktree/main commits. Every source ref and its commit must reconstruct from the map chain, and every commit must have a tree result. No ref can disappear merely because its tree duplicates another's.

Each observation record binds actual fetch command/result, actual ref-list and batch-check provenance, start/completion timestamps and sequence. A compact command-output representation must itself reconstruct exact original stdout/stderr bytes or retain those bytes once as a digest-addressed blob; recording only their hashes is not durable custody. Preserve byte-identical shared blobs once, including across preparation directories. Canonical mapping representation and exact raw command serialization are distinct: do not claim reconstructing one recovers the other without a specified encoding proof.

A reconciliation completes only after its entire native ref/tree observation is available; select the latest completed observation before readiness's actual completion using monotonic times. Readiness is invoked once. Obtain actual GitHub readbacks at or after that selected reconciliation. Full reconstruction and byte accounting must not relabel time or remove any relevant ref. Selection can fail honestly if no eligible fresh observation exists.

Budget design: allocate the existing4MiB operational diagnostic budget across initial snapshot+content table, deltas, actual commands/readbacks, selected timestamps/absence, and failure record. Root launch/config slots and all other128MiB allocations remain fixed. Reserve a fixed failure record slice BEFORE accepting more mapping bytes. Precompute encoded byte lengths before exclusive writes. Stop before accepting an observation whose complete durable representation cannot fit; never delete prior evidence. A bounded truncation of diagnostic prose must be explicit, with the exact reason and byte counts; it cannot stand in for unretained native evidence.

There is no uniform sublinear encoding bound for arbitrary ref churn. If every name changes to unrelated IDs, a delta can be as large as a full snapshot; if the initial required map already exceeds its allowance, refuse. Derive exact B = B_initial + sum B_delta_i + B_unique_tree_entries + B_unique_raw_blobs + B_observation_headers + B_failure_reserved. Accept only B<=4MiB and separately total<=128MiB. Do not promise successful preparation for all future repository states. The intended improvement is avoiding repeated unchanged entries, not overriding an information or resource bound.

## Explicit review corrections

Supported ref names must round-trip under strict UTF-8 without replacement, normalization or omission. Ref-list framing uses the exact native delimiter specification; reject any input that cannot be parsed unambiguously into names and object IDs. Canonical ordering compares the encoded UTF-8 bytes, not locale collation. A decoder/framing failure invalidates that observation; it is never mapped to ABSENT. This narrows supported inputs instead of claiming all possible native names are accepted.

Every eligible reconciliation and readiness observation must record the same host/boot clock-domain identifier and monotonic clock choice. Reuse across incompatible boot/clock domains is refused. Preserve actual precise completion values and the actual second-resolution UTC serialization used by the native launch schema. Selection must also satisfy the unchanged native300-second freshness gate at invocation. Latest-before-readiness alone is insufficient.

Claims-tree representative equivalence is limited to parsed record-conflict/epoch decisions under successful available-object reads, identical local claims, stable parser/configuration and the same relevant time predicates. It is not equivalence of command failures, timeouts, bytes read or wall-time behavior. Published binding ancestry checks remain intact. The native fence's source-level content-only premise and its independent timing obligations are detailed in the review.
