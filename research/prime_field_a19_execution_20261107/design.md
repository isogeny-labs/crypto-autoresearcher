# Prospective fixed unknown-pool discriminator

The lead is whether a bounded unlabelled auxiliary set produces information
about an unchanged factor base after eliminating every new unknown. Its finite
test is deliberately distinct from a further known48 coverage extension.

The old norm32 points, common prerequisite64 projection and unknown order stay
fixed. Baseline M contains only norm source decompositions for AP0 source128.
It excludes helper units, source constructor anchors and all target construction.
The own query stream must contain M in all three arms; mathematical sharing
never supplies another arm's cache or constructor anchors for free.

Unknown16 uses SHA256(domain|unknown-pool|full EC1 curve UID|index|counter),
reduces to x, chooses canonical rational y, verifies subgroup membership and
rejects old norm/previous pool sign classes. First success per index, at most
10000 candidates, no scalar recipe or yield-based selection. Its API retains
all sixteen native slots as auxiliary coordinates. Legitimate public prerequisite
or source/constructor coincidences remain explicit own known equations; there
is no redraw to force an unknown. Every candidate/rejection/hash/root/subgroup
and stored point payload has its own counters. The public known16 control pays
the existing public-label constructor independently and never reveals pool logs.

The three programs independently execute the A15 batched pair floor, actual
scalar and NumPy batch endpoint engines, AP0 sources, natural queries, full
GENERAL8 constructor predictions/tables/P/Q caches/Registry and all64 logical
target slots. Native signed aliases do not manufacture distinct triples.
Requested eight target coordinates remain distinct from auxiliary variables.

For both source-only and complete row streams, project only through COMMON
prerequisite units. Remaining auxiliary slots and actual target coordinates
jointly form U. The total old-base information is

    Delta = rank([[M,0],[B,U]]) - rank(U) - rank(M).

K_source consists of own non-collected source units/cache matches/anchors.
K_full additionally contains pure-P Registry base matches (zero target block),
with original provenance retained. Each K block is cancelled by the same rule.
Its Delta is supplied constructor information; total Delta minus own K Delta
is the incremental information after buying that knowledge. Source/full K
scopes are explicit, so future target construction cannot enter source-only K.
Complete minus source Delta measures the target-stream marginal. Direct gain
uses rows with U already zero; cross gain is total minus direct gain. All these
quantities retain independent dense ranks, complete left-kernel basis weights,
native lifts and old-kernel syndromes. Rank(U) can be smaller than U's width.

Recovery cancels remaining auxiliary columns after declared supplied-unit
substitution, then solves old-base plus requested-target coordinates. Named
target unit membership, negative residuals, original native weights and public
scalar equations are checked against a separately executed full native joint
solver. Deficient old-base rank is compatible with target recovery. No query
is skipped on that basis in an unknown-base arm.

Costs are separate Fp/Fr primitives, hash/root/pow/subgroup/sign/alias operations,
logical work and explicit payload/NumPy array bytes. Construction, collection,
matrix assembly, cancellation, elimination, identification, lifting/public checks
and storage remain visible. Physical dual-engine work and conditional single-engine
views are separate. Information diagnostics/native controls/checkers and shared
curve/norm fixture generation remain separately retained, not hidden in primary
solver savings. Complete calibration, interpreter/NumPy/OS/IO and some primitive
internals remain unexpanded; no byte-as-operation or weighted cost convention.

The fixed outcome may be positive, zero, K-only information, changed target masks,
or an operational cap/failure with remaining cases unknown. No favorable outcome
is required and no pool, curve, target or horizon can expand after outcomes.
The prospective protocol/source assessment and normal release/admission retain
native48/joint64/pairs8192/rows4096/labels8192/cache64 and original resource bounds.
