# Next discriminating lead: fresh progression sources against an optimized hash baseline

Proposed next action only, 5 November 2026. This is a read-only research
assessment apart from this note. No protocol, approval, release, official
scientific status, new idea/task record, implementation or trial is created.
The parent owns any subsequent exact-source design, freeze and run.

## Rank one action

Implement one matched fresh-holdout comparison of public sources
`[a+i*d]P` against independently hashed public scalar sources, with optimized
construction and kernel-free certificate recovery available to both methods.
The question is whether the cheap progression walk retains enough independent
base information and natural-target recoveries to justify its complete cold
cost. Correlated sources could lose rank, duplicate equations or miss targets;
those outcomes must be retained. Arithmetic progressions, fixed-base tables and
row-space membership are established techniques; this is an implementation and
finite-distribution comparison, with no novelty or expected speedup claim.

A separate full panel that merely removes kernels from the same observed A7
inputs ranks below this fresh comparison. Kernel-free recovery is a necessary
shared baseline control here, implemented and checked before fresh outcomes,
rather than a reason to postpone fresh curves and targets again.

## What the checked work establishes

The completed corrective A9 analysis at raw-data commit
`4d736301299e25b0f582c57b7829ad5c6ec165d7` records 1,152 verified solver calls on
288 reused systems. Clean Fr multiplication totals are 1,616,582 dense joint,
813,356 dense cancellation, 688,054 sparse joint and 605,078 sparse cancellation.
Their kernels, certificates and target outcomes agree, with exact archived A8
controls for the dense modes. These are component counts, not interchangeable
units of total cost. The old four observed/unverified outputs remain charged:
two physical attempts, 1,156 observed completed producer calls in the campaign.
No old protocol, assessment, failure record or native source is amended here.

The new sparse baseline exposes a different boundary: joint identification uses
10,052 Fr multiplications versus 86,612 for cancellation, while kernel creation
uses 136,564 versus 57,630. Whole identification phases also perform certificate
reduction, so their totals cannot simply be subtracted as avoidable dot products.
Cancellation is not uniformly cheaper in every component/case. Removing an
optional kernel from both methods could change comparisons and must precede
claims about the stronger implementation.

A7 construction still calls binary `e.mul(s,P)` separately for each uncached
hashed source, and constructs the original 64 public anchors with 64 such calls.
The repository already has `FixedBaseMultiplier`: charged positional tables,
windows 1 through 8, exact scalar bounds and tests against ordinary multiplication.
The historical repeated-target benchmark fixes window 4. Thus A7's construction
path is not the strongest implemented reference for the next source experiment.

## Proposed bounded fresh panel

Freeze rules before generating any fresh fixture or target. A concrete bounded
panel is two curves each at p=8191/base16 and p=65537/base32, eight new independently
hashed canonical-y public targets per curve, and three predeclared AP/hash seed
pairs (0, 1, 2). Use a new domain, for example
`prime-field-ap-source-holdout/20261105/v1`, with separate curve, target, start,
step and hash-source tags. Exclude the explicitly enumerated prior A4/A6 curves
and previously selected new curves before accepting the first eligible candidate.
Bind the actual exclusion list; do not claim a corpus-wide absence of reuse.
A frozen isomorphism-duplicate rule can strengthen that exclusion without using
yield. Select nonsingular nonzero-b curves with prime group order different from
p and sufficient base atoms, with the existing finite candidate gate. Never
select a curve, source seed or target by relation yield, rank or recovery.

For each AP seed, derive a nonzero start a and step d modulo the prime order r,
with a frozen counter limit. Set `s_i=(a+i*d) mod r`, i=0,...,127. Because d is
nonzero and r>128, scalars are distinct; reject an entire candidate pair only
if a zero occurs in the declared 128-term horizon. Retain every rejection trace
and charge derivation. No rejection for opposite points, base/source coincidences,
low rank or target coincidences. Construct A=[a]P and D=[d]P with the strongest
applicable charged constructor, then use `Q_0=A; Q_(i+1)=Q_i+D`. The walk costs
127 additions after its two starting scalar constructions at full budget; zero
and exceptional group-law cases remain actual measured work.

The matched hash seed generates 128 distinct nonzero scalars with a separate
public hash recipe and exact candidate trace. All seeds and draws are retained.
Public labels are allowed for source construction; fresh target scalar labels
must never be generated, stored as sidecars or passed to the solver. Source/base,
source/target and target/target coincidences stay visible rather than triggering
success redraws.

Retain budgets 0/8/16/24/32/48/64/96/128, relation-only and explicit-anchor views,
fixed original projected columns per curve, and all eight target slots regardless
of rank/recovery. This gives 432 dependent curve/schedule/budget/scope observations,
not 432 independent experiments. Run both joint and cancellation row-space solvers
cold on each system: 864 bounded solver evaluations. The four curves and 32 target
points are the independent draws described by the rules; schedules and prefixes
reuse them.

Reuse one signed pair table and one target-query stream per curve. With six
128-source schedules, the proposed physical source-query total is 147,456;
shared target queries are 1,536 and pair entries 4,928. A separate complete signed
triple oracle enumerates 88,320 triples once over the four curves and checks every
source/target bucket. These are proposed counts, not executed work. The row/pair
and memory gates must refuse with retained prefixes rather than truncate samples.

## Strong construction controls and knowledge boundaries

Port or adapt the existing positional-table algorithm to the same instrumented
Fp group implementation used by the collector; the current production `Curve`
counts group operations but does not expose the old collector's full Fp vector.
Do not obtain an apparent saving merely by changing instrumentation. Meter cold
table construction, all online additions, memory and scalar/digit processing.
Provide the same exact prerequisite cache to both methods, with no free future
or cross-schedule points. Construct the shared original 1..64 anchor prerequisite
by a charged public walk rather than 64 independent binary multiplications.

Freeze a workload-only constructor policy before seeing fresh rank/target results.
At minimum include the supported positional windows and an ordinary-multiplication
control: a public-scalar digit-count rule may choose the minimum cold group-call
count, with tie-breaking and any look-ahead horizon specified. A width chosen
for a 128-source horizon need not be optimal for stopping at eight sources.
Report that boundary. For a stronger reference, retain the separately charged
window-family controls and its measured primitive Pareto envelope; source/query
rows are identical across constructors and need only be collected once. Physical
control construction costs still belong in the campaign. Do not call a chosen
window globally optimal in Fp/Fr/CPU cost or best among unimplemented methods.
AP's two starting multiplications receive the same constructor choices; forcing
it to buy an unnecessary hash-sized table would also bias the comparison.

Construction creates information as well as points. Retained fixed-base table
entries and AP's step D have known public scalars; intermediate labelled points
can coincide with base atoms or targets too. Prospectively define and record the
available labelled construction points, uniformly across constructors, and charge
their scans/storage. Their known base coordinates become explicit anchor rows;
known target coincidences become explicit public target certificates/diagnostics.
Do not silently shrink U, hide a table-created recovery or pretend that only
queried source points were public. Report relation-only and fully declared anchor
views separately, with construction-only recoveries distinguishable from relation
information. Prefix knowledge means charged/computed availability, not secrecy of
public hash recipes or a claim that other public computations are impossible.

## Shared linear-algebra baseline

Both current identify methods already reduce the functional against certified
pivots and carry original-row weights. Over a consistent field system, a zero
residual is exactly row-space membership and supplies the value/certificate.
Use that test directly for both full joint unit functionals and cancellation
representatives, without constructing every right-kernel vector or computing
vN solely to duplicate the decision. Keep insertion order, pivot policy, full
original-row weights, RHS checks, cancellation construction and certificate
lifting identical where applicable. Missing target groups remain unidentifiable.

Retain nonzero residuals and the certified echelon system for negative cases;
an independent dense checker verifies nonmembership/rank and all positive
original-row and public [k]P=Q equations. If a self-contained dual nonmembership
witness is required, construct/check it explicitly and charge that work rather
than treating it as a free kernel. Full kernels may be computed by the checker
as a separately charged control; they are not mandatory producer recovery output
in a fresh contract. Old A9 complete-kernel promises remain immutable.

Before native fresh generation, tiny and actual JSON-roundtrip controls must
compare kernel-free decisions/values/original weights with the existing sparse
solvers, including deficient/full/empty systems, absent targets, nonunit vectors,
false negative residuals and corrupted coefficient/RHS/public certificates.
Apply the same improvement to both representations, retain adverse vectors,
and do not certify cancellation against a baseline still doing redundant work.

## Decision quantities, complete retained costs and limits

Compare source-only rank and original-column nullity, normalized distinct equations,
natural single/joint target recoveries, first checked recovery budgets, and the
base information remaining after cancelling target columns:
`Delta=rank([[M,0],[B,U]])-rank(U)-rank(M)`.
Keep explicit anchors, direct public recoveries and genuine multirow cancellation
separate. A larger augmented rank from extra target columns is not a gain in
base information. No full factor-base rank requirement precedes natural recovery.

Retain cold generation/rejections, public prerequisite construction, scalar
recipe/caches/table setup, all source/target queries and failed buckets, extraction,
sign/certification/projection/normalization, elimination, membership, cancellation,
lifting, original-row/public checks, diagnostics and storage/IO. Measure constructor
and solver phases separately from shared physical work and independent checker
cost; give both one-arm cold and actual-panel totals. Budgets/views reuse physical
work and must not multiply it. Count Fp and Fr add/sub/mul/inv separately, retain
logical lookups/visits/bytes, and do not sum overlapping group/Fp counts or invent
weights. Unmetered inversion internals, hashing, sorting and Python/IO remain
explicit; inclusive process CPU/wall/RSS retain their actual scope. Shared-host
clocks do not support an isolated timing-speedup claim.

Retain all outcomes and every failed/partial attempt. If AP saves construction
but loses target/base information, that is a discriminating result. If apparent
gains disappear with the fixed-base or kernel-free controls, record that boundary.
Only a complete matched cost model and further independently frozen evidence can
support broader attack-cost conclusions; no automatic overall-goal completion
follows from this proposed finite test.

The execution route remains prospective: exact source/inputs/rules published,
complete source-bound frozen protocol, real canonical S3 checkpoint and explicit
root release before mathematics. One existing local process/thread, 2 GiB,
21,600-second CPU/wall protective watchdog and one recorded attempt; no automatic
retry, new paid cloud capacity or transfer to another pool/provider. A fresh
contract must state its own absolute deadline and campaign accounting rather than
reuse the exhausted original A9 release. This note authorizes no launch.
