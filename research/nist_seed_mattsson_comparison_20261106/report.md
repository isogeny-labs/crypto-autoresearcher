## Exact identities

All 19 external seeds, candidate ordinals, field primes, a=-3 coefficients, SHA-derived c parameters, group orders, and signed traces match the canonical archive. Rows are joined by the complete 160-bit seed, then bound to full curve UIDs. Eighteen b coefficients match exactly. Published P-224 has the opposite b sign; this is a different equation for the same F_p-isomorphism class, not a curve-order discrepancy.

For P-224, compare.py finds a quadratic nonresidue d, sets u=d^((p-1)/4), and checks u^4=1 and b*u^6=-b mod p. The map (x,y) -> (u^2*x,u^3*y) therefore sends the archived model to the external model while retaining a=-3. The explicit witness is retained in comparison.json. All three omitted P-224 b coefficients match without a sign change.

## SEA definitions and discrepancies

The archived profile uses Delta=t^2-4p. For odd prime ell it keeps strict Elkies (+1), Atkin (-1), and ramified (0) separate. This replay independently recomputes all 3,173 retained symbols using integer modular exponentiation and confirms every stored signature. Every external below-100 list is a complete partition into +1-or-0 versus -1; there are no unexplained list-membership mismatches.

The external table places 31 ramified entries in its “Elkies” lists across 16 curves. For example, prime192v1 includes 5 and 11 with Delta=0 mod ell. This is a classification convention difference; treating these entries as strict Elkies primes would be incorrect.

The table describes its cutoff as a product M > 2^(L/2+2), L=bitlen(p). With the external +1-or-0 convention, the literal formula reproduces 15 of 19 reported values. The four exceptions are:

| Curve | Reported cutoff | Literal stated formula |
|---|---:|---:|
| omitted 239-bit ordinal 36 | 179 | 181 |
| omitted 239-bit ordinal 2682 | 157 | 179 |
| omitted 192-bit ordinal 2198 | 149 | 163 |
| prime239v2 | 191 | 197 |

The previously documented alternative M > 2^(((L-1)//2)+2), still including ramified primes, reproduces all 19 values. This is a reconstruction of numerical output, not verified author code, and was not newly fitted in this pass. It accounts for the discrepancies as an integer bit-length convention; the table's written formula and numerical values remain inconsistent in those four rows.

The archive's strict cutoff instead uses only +1 primes and M^2 > 16p. It agrees with the reported cutoff in five rows and is later in fourteen. Both the ramification convention and the threshold definition matter. All row values appear in comparison.csv. Neither cutoff is an observed SEA execution trace or runtime measurement.
