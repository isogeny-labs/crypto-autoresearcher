- **Last updated:** 2026-10-28 UTC.

## Problem

The repository contract requires the current PR head to have all required and applicable checks complete before merge, and requires `progress-fidelity` CI through branch protection. Earlier on 2026-10-17 UTC, several PRs merged before checks finished. At that time GitHub reported `main` as unprotected, no active repository rulesets, and Actions disabled. The workflow file existed, but those settings did not enforce or run it. Later the owner authorized Actions and a main ruleset requiring `progress-fidelity`. On 2026-10-25, `artifacts` was added to that required set after an oversized-file PR merged with its artifact check failed. At 05:21 UTC on October 26 the active ruleset was updated and subsequently read back with zero rules. PR #2583 merged at 05:35 UTC despite a failed formal-workspace check. At 16:49 UTC the owner-authorized required checks were restored. A controlled merge-blocking test remains open, and a passing check seen after merge would not satisfy the pre-merge rule.

This is a delivery-integrity issue for changes to the ICPERF goal and any other PR on `main`. It does not alter the scientific status of any run or prove an error in the merged content.
