Status (2026-10-30 06:50 UTC): local controls, three real-cloud Semaev fixtures, and two nonempty generic checkpoint states have completed. All four nonempty source/restore rows pass independent generic checks and reference bytes across distinct pods; see `reports/checkpoint-matrix-cloud-001/`. Frontier disk admission and worker integration remain outstanding. The producer's original composite four-arm registration gap remains explicit in report002; it is not silently repaired by later controls. Development-stage descriptions below are historical context.

The second bounded-export attempt was interrupted by node shutdown during degree-five production. See `runs/bounded-lift-terminal-002.json`. Stage-start receipts survive, but contain no matrix state. The current general job tool has no on-demand placement selector. The resumable tool accepts only native ecbench specifications on c8a.2xlarge, not an arbitrary Semaev producer. Do not mislabel this computation as an ecbench workload to pass that interface.

## Required resumable state

Implement a separate producer, preserving the qualified bounded-export source unchanged. Reconstruct the deterministic provisional monomial map from the immutable seed, then restore the relation matrix and loop position. A completed seed-phase chunk checkpoint must include: format/version, seed digest, instrument identity, N/D, working-coordinate and border counts, chunk size, phase, next variable and row offset, completed closure-round count, relation rank, exact row width, and the first rank rows of the echelon matrix. Reconstructing the provisional map can repeat work; it does not change the mathematical input.

For the closure phase, start with checkpoints at completed round boundaries. A within-round checkpoint cannot reconstruct the round's fixed low-row matrix from the evolving relation matrix: it must retain that fixed matrix and the next variable/chunk, or restart the entire round from its saved initial state. Do not skip these dependencies. A stable-rank round must retain its completion flag so restart can proceed to export without inventing convergence.

Persist only completed operations. Write a new snapshot to a temporary file, flush/fsync, close, then atomically rename. The worker uploads immutable snapshot objects and a manifest containing full hashes, lengths, input and executable identities, and progress metadata. Publish the manifest only after the objects are durable and read back with matching hashes. Restore the newest fully verified compatible manifest; never select a partial file or an unverified latest pointer. Retain at least one prior complete checkpoint until the new checkpoint is verified. Do not overwrite prior attempt evidence.

Use streamed serialization with bounded buffers. Include checkpoint I/O buffers and concurrent live matrices in memory admission. Account for ephemeral disk needed for old/new snapshot files and transfer staging; the prior 10 GiB pod limit is not automatically sufficient. Avoid a second full matrix copy merely to serialize. Upload must finish or explicitly fail before deleting a checkpoint. An interruption during serialization/upload should leave a usable prior checkpoint.

## Restore and correctness gates

Reject wrong seed, executable, dimensions, chunk schedule, invalid phase/offset, rank beyond coordinate count, short/trailing data, nonzero padding, and content-hash mismatch before using state. Shape checks do not prove matrix provenance; hashes bind a trusted producer's completed snapshot. The final certificate must still pass the original independent checker against the original system and a fresh exact count. A resumed producer's successful exit is not certification.

Required qualification: uninterrupted versus stop/restore byte equality on existing generic and Semaev fixtures; interruption after each seed chunk boundary and completed closure round; stable-round export restore; fresh and restored killed-constant outcomes; malformed/truncated/wrong-input snapshots; interrupted upload and manifest publication; repeated restore with no skipped/duplicated scientific inputs; original checker acceptance and exact count comparisons. Include a fixture with multiple closure rounds and multiple chunks. Record all failures as well as successes. Checkpoint timings remain L0 telemetry only.

## Initial candidate interface

`quotient_lift_checkpoint.cpp` includes `quotient_checkpoint.hpp` and retains the ordinary seed/output/chunk/memory arguments. `SEMAEV_CHECKPOINT_DIR` enables immutable numbered snapshots. `SEMAEV_CHECKPOINT_RESTORE` selects one verified snapshot; each binary rejects snapshots from a different executable or seed. `SEMAEV_CHECKPOINT_STOP_AFTER` exits75 after a chosen number of completed snapshots for qualification. `SEMAEV_CHECKPOINT_PUBLISH` optionally names a synchronous executable hook receiving the snapshot path as its only argument, with no shell interpolation. A nonzero hook status stops production. The durable publication/retention hook is not yet implemented; without it, snapshots accumulate locally. Do not launch this candidate at frontier scale in that mode.

The initial candidate checkpoints each completed seed chunk and completed closure round, plus the ready-to-export state. Serialization streams active echelon rows; content SHA256 is stored as a footer. Atomic rename and file/directory fsync complete before a publication hook. The build record is runtime/checkpoint-producer-build-001.json. Compilation is the only validation so far. Qualification must cover the full design gates above before scientific use.

## Publication hook candidate

`publish_lift_checkpoint.py` implements the synchronous hook interface as a separate, unqualified component. It validates the snapshot footer and frozen context, conditionally PUTs immutable content-addressed objects, streams complete GET/hash verification without a second matrix-sized disk file, and publishes an immutable manifest only after object verification. It verifies the manifest by GET before acknowledging it. Optional local pruning removes only the submitted snapshot after both readbacks; it never removes remote objects. Receipts go to stderr so the producer stdout remains its single result JSON. Single-object uploads above5,000,000,000bytes are refused pending a separately qualified multipart path. Snapshot selection/download for a replacement worker is still to be implemented.

Environment adds SEMAEV_CHECKPOINT_S3_PREFIX, SEMAEV_CHECKPOINT_CONTEXT and optional SEMAEV_CHECKPOINT_PRUNE_LOCAL=1. The context JSON must bind request, protocol, seed and binary SHA256 values. This candidate has syntax validation only. Mock interruption/idempotency/mismatch controls and actual cloud publish/restore/checker controls remain required. The running local producer qualification does not exercise this hook and is not changed by its addition.

## Restore downloader candidate

`restore_lift_checkpoint.py --prefix S3_PREFIX --context CONTEXT_JSON --out DIRECTORY --receipt NEW_RECEIPT` enumerates immutable manifests, checks complete listing and manifest hashes, and requires exact frozen context equality. It considers descending checkpoint sequences, records rejected candidates, streams the snapshot into unique temporary storage, verifies content/footer/header metadata, then atomically installs and fsyncs the restored file. Existing matching local files are reusable; mismatches are refused. The tool holds a local restore lock and never launches the producer or deletes remote objects. A success receipt contains the exact path to pass as SEMAEV_CHECKPOINT_RESTORE; no compatible checkpoint returns3. Same-sequence manifests have deterministic digest ordering; incompatible or damaged entries are recorded before considering older candidates. Syntax validation only so far; actual listing pagination, transfer failures, fallback selection and producer use remain unqualified.
