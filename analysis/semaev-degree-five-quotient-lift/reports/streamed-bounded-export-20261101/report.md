# Bounded certificate streaming qualification

The bounded exporter now accepts `-` as its output path. In that mode it writes the same binary certificate bytes to standard output and its final JSON status to standard error. The existing file-output mode and certificate format remain unchanged. A caller must capture the stream and require both producer exit zero and a `candidate_certificate` status before treating it as a candidate; the original independent checker still decides whether it certifies nonmembership.

The [local build](build.json) and [three-fixture result](result.json) bind the source and binary hashes. For each frozen fixture, file and streamed output had identical SHA-256, matching the fixture's expected certificate hash. The independent checker accepted each streamed certificate through `/dev/stdin` fed by a real producer pipe; no intermediate certificate file was used for that check. This tests stream framing and checker compatibility on small systems. It is not a D5 frontier trial or a measured storage solution.

For the n51 polynomial-00 D5 candidate, the accepted D4 seed has 2,893,164 next-degree monomials and 103,867 working coordinates in the read-only profile. The writer emits a 32-byte header, eight bytes per monomial mask, and `8 * ceil(q/64)` bytes per monomial row, where `q` is the **new D5 codimension**. Because `q` is unknown before closure, the certificate size is not fixed by the D4 seed. Its source-derived ceiling at `q <= 103,867` is **37,587,986,720 bytes**. The existing 96 GiB pod capacity probe found 10 GiB of allocated ephemeral storage, so a full cloud trial requires a durable streamed upload and a separately checked readback path. This PR supplies only the native stream and pipe-checker primitive for that route.
