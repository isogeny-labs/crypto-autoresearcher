# A total operation bound for saturated strict Boolean closure

2026-11-09. Proof-only algorithm analysis; no solver runs, benchmarking, builds, or cloud work. This generalizes the independently reviewed cap-four queue argument in `no-wrap-uniform-cap-four.md`.

## Domain, notation, and representation

Work in B_N=F2[x_1,...,x_N]/(x_i^2+x_i). The strict degree-D closure W_D is generated by input rows of actual degree at most D, linear combinations, and variable products x_i f when deg(f)+1<=D. Boolean reduction takes place after each multiplication. Set

    M = sum_(j=0)^min(D,N) binomial(N,j),
    L = sum_(j=0)^min(D-1,N) binomial(N,j)

for D>=1. For D=0 take L=0 and M=1. Let R be the number of supplied input rows offered for insertion, including redundant and zero rows. Canonical ANF extraction, validation, input reading, and creation of those rows are separate costs.

The algorithm uses dense M-bit rows. Monomials are ordered by decreasing degree, with any fixed tie order. A basis row's pivot is its first nonzero coordinate. Every stored row is immutable after insertion. Candidate reduction traverses existing pivot rows in pivot order; if its corresponding bit is one, XOR that basis row. An independent nonzero reduced candidate is installed at its first nonzero coordinate. This is forward echelon insertion, not a claim that all stored rows are reduced against future pivots.

## Complete feedback algorithm

1. Insert every input row of degree at most D.
2. Whenever an independent new row has pivot degree at most D-1, append that row to a queue once.
3. Remove one queued row and attempt to insert each of its N Boolean variable multiples. Any newly inserted eligible rows enter the same queue.
4. Continue until the queue is empty.

A pivot of degree at most D-1 implies actual row degree at most D-1 because higher-degree monomials come first. If D>N, all rows are eligible. At D=0 there are no eligible products and the initial row span is the closure.

**Theorem.** At termination the stored row span is exactly W_D, including every feedback round after degree falls.

Every insertion is an allowed consequence, so the current span is always contained in W_D. Conversely, in any echelon basis with the specified monomial order, the rows with low-degree pivots span exactly the intersection of its row span with B_(<=D-1). To prove this, take a nonzero linear combination of basis rows. The first pivot among selected rows cannot cancel: every row with a later pivot is zero at all earlier coordinates. Therefore a combination involving a high-degree pivot cannot have low degree. The eligible rows span the entire eligible intersection, including after new rows arrive. When the queue is exhausted, the variable multiple of every such basis row belongs to the span. Linearity gives the same for every polynomial in the eligible intersection. Thus the final span is closed, contains all required inputs, and equals the minimal closure.

Immutability does not invalidate the argument: later rows may introduce new pivots to the right of entries in older rows, but they cannot cancel the first pivot of an older selected row. No previously processed row needs to be processed again. This accounts for saturation feedback without assuming that one initial Macaulay matrix suffices.

## Explicit candidate and row-XOR bounds

There are at most M successful independent insertions, one per pivot. At most L have eligible pivots, so the algorithm processes at most L queue items and attempts at most N L variable-product insertions. Including inputs, the number of Gaussian insertion attempts is at most

    A = R + N L.

Each attempt XORs at most M basis rows, once per pivot position, so the total number of whole-row XORs is at most

    A M = (R+N L) M.

These are combinatorial upper counts for this specified algorithm, not measured values or bounds on another solver's internal instruction stream.

In a unit indexed-bit-access arithmetic model, an M-bit row XOR takes O(M) binary operations. Pivot traversal, testing, and copying fit the same conservative per-insertion bound O(M^2). Generating a variable product scans a row's at most M positions and XORs its coefficient into the Boolean monomial-union position. Hence

    total binary arithmetic cost = O((R+N L) M^2),
    dense basis storage = O(M^2) bits.

The queue needs O(L log(M+1)) bits of row references; stored pivot metadata uses O(M log(M+1)) bits. Input rows may be streamed, so retaining R M bits is unnecessary. A materialized monomial-union lookup table additionally uses O(N M log(M+1)) bits; alternatively compute union indices on demand and charge the indexing cost separately. Thus O(M^2) is the dense *algebraic row storage*, not an assertion that every indexing-table implementation has that same total bit size. Ordinary machine address calculations, combinatorial ranking, and Turing-machine access overhead are not included as unit-cost binary arithmetic instructions.

One implementation option uses monomial bit masks and on-demand rank computation; storing all masks costs O(N M) bits. Monomial union and ranking are polynomial in N and D using explicit binomial tables, so this adds a polynomial indexing overhead to the displayed arithmetic bound. No exact native instruction constants are claimed.

For fixed D<=N, M=O(N^D) and L=O(N^(D-1)), giving O((R+N^D)N^(2D)) binary arithmetic operations. If R=O(N^D), this is O(N^(3D)). Cap four recovers O(N^12) and O(N^8) dense row bits under the earlier R=O(N) family input bound.

## Exact finite-selector consequence

For any exactly reconstructed finite-selector system with N Boolean variables, cap D=N+1 is sufficient for the full ideal: every Boolean polynomial has degree at most N, so every variable multiplication is allowed. Here M=L=2^N and

    A <= R + N 2^N,
    row XOR count <= (R+N 2^N) 2^N,
    binary arithmetic cost = O(R 4^N + N 8^N),
    dense algebraic row storage = O(4^N) bits.

At N<=12, these are finite, explicit algorithmic bounds with M<=4096; they are not a recommendation to execute closure instead of simpler exhaustive truth-table evaluation. Exact code-solution enumeration uses only 2^N equation evaluations and directly computes the truth table of the generated Boolean ideal. Enumeration alone does not reconstruct the smaller-cap W_D filtration or determine the exact last fall degree.

For D=0,...,N+1, separately computing all closures and testing whether W_D contains every ideal polynomial of degree at most D yields an exact LFD decision route when combined with the exact solution-set evaluation map. More precisely, d_F<=d holds exactly when I intersect B_(<=e) is contained in W_e for every e from d through N+1; checking only the first apparently successful cap is not the stated criterion. The full ideal and each intersection I intersect B_(<=D) can be obtained by linear algebra on evaluation at the exact solution assignments. This is a possible complete algorithm, not a completed CLI feature or an execution claim. Its extra evaluation/intersection operations require separate accounting; the displayed bound concerns each closure computation.

For a CLI using N<=12, a safe theorem-derived operation label must bind N, D, R, exact ANF equations, the strict-cap convention, the specified algorithm and arithmetic model. Counts such as A and A M can be reported exactly from those parameters without claiming that an F4/F5/F6 or SAT backend actually performed them. Invalid-code constraints, repeated selector values, shared bits, and auxiliary variables must be reflected in the actual reconstructed system before selecting N or R.

## What the bound says about other backends

This theorem proves existence of a total finite closure algorithm, with feedback included, and bounds that algorithm's mathematical operations. It does not bound the wall clock, memory allocator behavior, number of learning steps, branching decisions, reduction strategy, or native instructions of a distinct F4, F5, F6, SAT, or SMT implementation. Such a backend may perform extra work, use different matrices, fail to implement this strict closure, or return after a different stopping condition. A backend-specific bound requires a correspondence proof and its own operation model.

A SAT model or UNSAT answer is a statement about solutions, not a certificate that the degree-D closure has saturated. Conversely a complete closure result at a cap is not necessarily a full solution characterization until its ideal/solution bridge is supplied. These distinctions matter when attaching operation labels to actual retained selector artifacts. The theorem supplies no automatic dataset admission and launches no work.
