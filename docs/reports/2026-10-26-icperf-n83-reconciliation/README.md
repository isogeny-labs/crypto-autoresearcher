# Koblitz N83 baseline in the requested subgroup range

**26 October 2026 — source reconciliation, no new trial or performance claim.** This report corrects the scope of the [16 October ICPERF baseline assessment](../2026-10-16-elite-factor-base-baseline.md). That assessment correctly identifies its locally reviewed `GF(2^53)` comparison as a 45-bit subgroup, but its statement that this is the only applicable Koblitz comparison is stale. The current cryptanalysis baseline ledger has an N83 Koblitz row whose prime subgroup has 53 bits. The row is a useful in-range reference with a specific uncharged phase; it does not fill the fully charged `m=2..8` grid.

## What the current source row measures

The ledger's current N83 producer is `koblitz-n83-rankfinder-20261021`, run `39527997793`. It used 12 fresh public points, 36 alternating primary pairs, same-point tuned `rT770` rho, two A/A pairs and one planted pair per point, with 282/282 recorded rows valid. The *source-reported* within-run predecessor/current cold ratio is `1.0196` with interval `[1.0147, 1.0255]`; its A/A cold ratio is `0.9982 [0.9928, 1.0036]`. This report has not rerun those arms or their independent verifier and does not promote that ratio as a new claim in this repository.

The same run reports normalized `S` of `0.4466` for IC and `0.1138` for rho, a **point** IC/rho ratio of `3.9242` with no interval computed in that run. The IC accounting comprises mean rank-stage wall `2,806.5 ms`, mean subsequent setup `4,308.5 ms` and mean online `158.6 ms` on one host class. These are source-reported means from the same protocol, shown as a phase map in the [editable chart source](phase-chart.py) and [vector chart](phase-chart.svg). The approximately `3.25 s` root-index build and `0.84 s` self-test are **inside** the 4,308.5 ms setup; adding them again would double count. The current row's linear algebra is represented by a verified load of a cached factor-log table.

**Charging boundary:** each N83 IC arm loaded a prepared K600 base from a file; factor-base construction was excluded. A separate replay on another host class measured `427.524 ms` to construct it. Adding that time to the current run would mix hosts and is only an illustration in the source ledger, not an accepted fully charged cold result or paired ratio. The reported `S=0.4466` is therefore a lower bound on the every-phase cold cost under nonnegative base-construction time. The source also says its current ratio is an upper bound on a common-base, every-phase *predecessor/current* improvement ratio; neither statement supplies a new matched every-phase IC/rho measurement. The [chart](phase-chart.svg) draws the excluded construction as a separate bar, with its different host clearly labeled.

The 16 October ICPERF report's `GF(2^53)` row and this `GF(2^83)` row have different curves, subgroups, implementations, target panels, timing units and rho arms. They are two references, not successive points in a same-instance comparison. The N83 row shows that the requested 50–63-bit **subgroup** range already has a Koblitz near-complete baseline. It does not change the absence of a fully charged three-family arity grid.

## Required next comparison

The current N83 recipe can serve as a frozen control for a same-host replay that includes target-blind base construction, rank generation, index building, linear algebra, target decomposition, verification and matched rho on the same held-out points. Retain failed attempts, cache provenance, wall/CPU and peak memory. A candidate orbit base, such as the separately measured K899 arm, must run against that exact current producer with its own construction charged; the older K899 result was paired against a different predecessor and cannot be combined with the current row by multiplying ratios. Cold `T=1` and explicitly reused `T>1` costs need separate totals. This is a proposed measurement boundary, not a Coordinator approval or dispatch.

For the full user request, prime and ordinary-binary pipelines still need complete 50–63-bit rows, and each family needs `m=2..8` cells or explicit frozen censored/unavailable dispositions. Direct `S_8` represents seven summands plus a target; eight summands require direct `S_9` or a correct chain. The [existing problem record](../../../problems/full-width-ic-arity-grid-unmeasured.md) retains these obligations.
