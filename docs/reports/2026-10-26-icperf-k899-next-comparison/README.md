# N83 K899: the next factor-base comparison

**Preparatory search record, 26 October 2026.** Question: does a larger, target-blind Frobenius orbit base reduce the *fully charged* cold cost of the current N83 index-calculus producer? This record reviews published mechanisms and existing internal receipts. It authorizes no experiment, changes no research status, and makes no new quantitative speedup claim.

## Literature and prior-work check

The relevant primary sources are [Semaev's summation-polynomial construction](https://eprint.iacr.org/2004/031), [Faugère–Perret–Petit–Renault's binary-field decomposition systems](https://people.maths.ox.ac.uk/petit/files/Eurocrypt2012.pdf), and [Huang–Petit–Shinohara–Takagi's FPPR improvement](https://doi.org/10.1186/s40736-015-0012-6). The first makes summation-polynomial decomposition a known mechanism. The second explicitly couples a factor base with its polynomial-system solver and makes its complexity conclusion conditional on a rank heuristic. The third motivates choosing a vector space by the structure of its product spaces; a sparse input or low product-space dimension alone is therefore neither novel nor evidence of a cheaper full solve. These are retrieved primary papers; the FPPR article was checked at its publisher page, while the full paper was not re-derived here. The local [factor-base choice](../../../knowledge/leads/ecdlp/ic-binary/LEAD-ICB-factor-base-subspace-choice.yaml), [Frobenius orbit](../../../knowledge/leads/ecdlp/ic-binary/LEAD-ICB-frobenius-orbit-factor-base.yaml), and [Koblitz setup](../../../knowledge/leads/ecdlp/ic-binary/LEAD-ICB-koblitz-setup-phase-cost.yaml) leads delimit existing tests. The repository's `search_knowledge`/`get_context` retrieval tools were unavailable in this session, so the checked local records and primary sources are listed explicitly; this is not a claim of exhaustive literature coverage.

## Discriminating design for Coordinator review

The first gate is **representation design and compatibility**. Freeze two distinct candidate arms before seeing targets: the nested **direct K899** base (899 factor-log columns and 899 indexed orbits) and a new multiplier-closure base with a predeclared pair `(K′, M)` chosen to yield roughly 899 *realized distinct* indexed orbits while keeping far fewer factor-log columns. The current M38 control is `(K′, M)=(16, 38)`, with 608 indexed orbits; the new closure is not the nested direct K899 set and must not inherit its name, timing or certificate. Construct each arm without targets, then independently verify every orbit, subgroup point, factor-log table, multiplier label, closure map, realized column count and index-orbit count. Preserve duplicate orbits and failed construction. If a candidate cannot be formed or certified, retain that result before proposing a timed comparison. This co-design tests the source's separation between the number of relations needed for rank (columns) and the number of root-index entries (orbits); neither input count proves a cost gain.

Then freeze the current N83 binary, subgroup, one-arity PDP4 recipe, independent held-out public targets, and rho reference. On one host, time all target-blind base constructions, certification, file loads and root-index builds. A cheap stage-only cost gate can precede the full target panel: if a candidate's **index build alone** exceeds the measured fully charged current-M38 cold total on that same host, nonnegative remaining candidate work rules out a cold `T=1` win for that frozen arm. The current M38 partial cold mean is `7.2735 s` before base construction, so it is not itself that fully charged threshold. The old direct K899 index time is likewise not a current-closure measurement.

For an admissible arm, run alternating matched target and rank seeds with A/A repeats and a planted relation. Retain every failed/censored attempt and the actual useful-rank increments, sparse matrix dimensions and density, full-point relation certificates, target scalar replay, CPU/wall/RSS, and cache hashes. Report cold `T=1` and explicitly amortized `T>1` totals separately; a cold loss can still leave an online or reuse-count question. Predeclare a wall/RSS guard for each representation. This is a proposed protocol boundary; it needs a complete `experiment.protocol/v1`, controls, sample/power plan, archive coverage, read-only preapproval result, and Coordinator decision before execution.

The *falsifier* for each narrow arm is a paired, fully charged cold total that fails to improve over the current M38 producer within a frozen effect threshold, or a construction/index cost that cancels rank savings. An online-only improvement would be recorded as such. A positive narrow result would justify an arity-specific extension, not a three-family ECDLP conclusion. Prime and ordinary-binary 50–63-bit rows and arities 2–8 remain separate obligations in the [full-width problem record](../../../problems/full-width-ic-arity-grid-unmeasured.md). Direct `S_8` represents seven summands plus the target; eight summands need direct `S_9` or a correct chain.
